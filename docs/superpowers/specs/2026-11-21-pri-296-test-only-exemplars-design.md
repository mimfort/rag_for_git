# PRI-296. Отбор тестовых примеров

Бриф задачи — `docs/superpowers/briefs/2026-11-21-PRI-296-test-only-exemplars.md`.

## Поведение

Секция `Test exemplars` должна отдавать тестовые файлы. Тестовые пути определяются существующим классификатором `_is_test_path`, в том числе для файлов поддержки внутри `tests/`. Поиск опирается на тот же набор подзапросов, гибридных кандидатов и соседей графа. После расширения графа фильтр допускает в файловый бюджет только тестовые пути. Если кандидаты закончились, секция отдаёт меньше файлов или штатную диагностику `(ничего не найдено)`. Ранжирование, дедупликация и бюджеты применяются к оставшимся кандидатам в текущем порядке.

Режим включается внутри `_TaskContextDeps.test_exemplars`. Публичный `search_codebase(include_tests=True)` по-прежнему допускает обычный код и тесты. Секция `code` по-прежнему использует текущий поиск с подмешиванием путей. Для тестовых примеров отдельный источник подмешивания и разметка фикстур понадобятся только при подтверждённой потребности в таких примерах.

## Выбор реализации

Фильтр после расширения графа сохраняет тесты, найденные по графовым связям от производственных символов. Он использует существующий индекс и форматы, а тестовые файлы конкурируют за все доступные им слоты. Фильтр сразу после гибридного поиска уменьшил бы число производственных вершин для расширения. Фильтрация внутри Postgres потребовала бы отдельно проверить покрытие кандидатов ANN и семантику распознавания путей. Выбран вариант с фильтром перед файловым лимитом. Общий пул гибридных кандидатов остаётся ограниченным.

## Приёмка

На PRI-278, PRI-291 и PRI-256 сравнить оба режима на одном индексе `dev@bfcefdf`, одинаковых тестовых подзапросах и прежнем файловом лимите. Для каждого запроса опубликовать состав секции, покрытие размеченных тестовых файлов, пересечение с `code` и задержку с условиями измерения. Модульные проверки должны покрывать конкурирующих кандидатов, тесты из графа и пустую выдачу.
