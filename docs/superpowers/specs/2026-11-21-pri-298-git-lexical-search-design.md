# PRI-298. Лексический поиск по Git-снимку для solve-task

Постановка и исходные материалы собраны в `docs/superpowers/briefs/2026-11-21-PRI-298-git-lexical-search.md`.

## Выбор подхода

Отдельный BM25 по ограниченному набору файлов Git даёт линии из конкретного коммита и обходится без перестроения индекса. Расширение постоянного индекса потребовало бы хранить и обновлять чанки новых типов на каждой ветке. Поиск по всему Markdown повышает шум: в исходном пилоте он дал 0 обязательных файлов в обоих корпусах. Широкий пул нужен для контрольного прогона.

## Источник

`context_limits.code_section.max_git_files` задаёт квоту от 0 до 3, по умолчанию 0. При включении секция `code` ищет по SQL, YAML, TOML и Markdown под `plugin/skills/`. Источник читает обычные текстовые Git-блобы из SHA указанной ветки, применяет эффективный `paths.ignore` и пропускает `eval/`, `docs/superpowers/` и тестовые пути. Изменения в рабочем дереве, ссылки, подмодули и бинарные файлы не читаются. Ограничения чтения защищают от отдельных больших блобов и слишком большого набора. Неудача Git оставляет обычную выдачу и диагностируется в `gaps`.

BM25 сортирует целые файлы по запросу задачи. Токены формируются из последовательностей букв и цифр длиной от двух без учёта регистра. Документ состоит из пути с удвоенным весом и текста, параметры BM25 — k1 = 1,2 и b = 0,75. При равных оценках сравниваются пути. Фрагмент содержит видимые строки около совпадения без превышения файлового лимита. Заголовок сохраняет формат существующих ссылок и несёт метку `git-lexical@<SHA>`.

Файлы Git занимают свободные слоты или вытесняют хвост гибридной выдачи. Подмешивание похожих diff сохраняет свой фактически занятый резерв. Источники используют единый потолок файлов и символов. Верификатор ссылок получает Git-фрагменты через ту же секцию `code`. Обычный `search_codebase` и `test_exemplars` не используют источник.

## Проверка

На двух фиксированных корпусах PRI-278 сравниваются выключенный режим, широкий лексический пул и ограниченный пул. Для каждого случая начальный Python-контекст берётся из сохранённой гибридной выдачи, Git читается на базовом SHA. Все варианты используют 20 файлов и 975 символов исходного текста на фрагмент. Полное совпадение старых 7/24 и 3/14 проверяется на этапе обнаружения кандидатов. Отдельно измеряются ссылки с подтверждёнными строками итогового брифа, покрытие обязательных Python-путей, фактический размер входа и задержка чтения и ранжирования. Данные о решениях задач остаются в оценщике. Включение по умолчанию требует улучшения покрытия новых типов и сохранения Python-ядра при сопоставимом бюджете и задержке.
