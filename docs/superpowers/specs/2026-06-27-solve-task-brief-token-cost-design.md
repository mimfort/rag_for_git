# Дизайн — Токены этапа solve-task в брифе

> Seed: `docs/superpowers/briefs/2026-06-27-solve-task-brief-token-cost.md` (board-less).
> Статус: согласован. Метрика — **4 бакета LLM-токенов** (fresh-in / output / cache-write / cache-read),
> авто-хук `PostToolUse`, флаг в `.review.yml`. **Долларов нет** — см. §1.1.

## 1. Контекст и цель

Скилл `solve-task` собирает контекст задачи и пишет **бриф** в `docs/superpowers/briefs/<date>-…md`.
Этап тратит LLM-токены (main-loop: ретрив, чтение кода, дистилляция). Пользователь хочет **опционально**
видеть в самом брифе, сколько токенов ушло на этап — чтобы сравнивать расход «с плагином solve-task /
без». Фича — на уровне харнеса/плагина, не в Python-ядре reviewer; доп. работа сборщика контекста — нулевая
(считает детерминированный скрипт по транскрипту).

**Ключевое требование:** число берётся из **транскрипта сессии** (JSONL), а не из самооценки LLM —
модель не может надёжно сосчитать собственные токены, а MCP-сервер не видит токенов разговора. Значит,
замер — **детерминированный PostToolUse-хук**, читающий транскрипт.

### 1.1 Почему только токены, без $

Проверено через `claude-code-guide` (офиц. доки Claude Code, `costs.md`):
- **Реальной (billed) стоимости на диске нет.** `/usage` показывает лишь **оценку**, посчитанную
  локально из тех же счётчиков токенов; авторитетный биллинг — только в Claude Console (API).
- В транскрипте на каждый ассистентский ход есть **только** token-счётчики + `model`; поля `costUSD` нет.
- Для Pro/Max-подписки per-session $ как факт биллинга не существует вовсе.

Любой $ в брифе пришлось бы **самим высчитывать** по прайс-карте (как `ccusage`) — это та самая «доп. работа»
и риск устаревания, которых пользователь просил избежать. Решение: **доллары не показываем**, выводим
только сырые токены по 4 бакетам. Прайс-карта (`prices.json`) из дизайна **исключена**.

## 2. Не-цели (out of scope)

- **Доллары / стоимость в $.** Нет надёжного on-disk источника (§1.1) → не считаем и не показываем.
- **Контрфактуал «без плагина».** Замер = токены *самого этапа solve-task*. Сколько ушло бы «вручную,
  без скилла» — пользователь меряет отдельно; авто-замер этого не покрывает.
- **Атрибуция субагентов.** До записи брифа `solve-task` не фанаутится (фанаут только при handoff в
  разработку, уже после брифа) → считаем только main-loop; субагентные транскрипты не агрегируем.
- **Изменения в Python-коде reviewer.** `.review.yml` парсится server-side через `yaml.safe_load`+`data.get`
  по известным ключам (`reviewer/policy/policy.py:31,71`); новый ключ `solve_task` молча игнорируется.
  Хук читает yaml сам — reviewer не трогаем.
- **Бэкфилл старых брифов.** Блок добавляется только при записи нового брифа хуком; ретроактивно не считаем.

## 3. Архитектура и поток данных

```
solve-task (main-loop)
   └─ Write(docs/superpowers/briefs/<date>-…md)        ← бриф записан
        │  (Claude Code PostToolUse, matcher "Write")
        ▼
   plugin/hooks/brief_cost.py  (stdin: tool_input.file_path, transcript_path, cwd)
        ├─ 1. path-guard: file_path под docs/superpowers/briefs/ ? иначе exit 0
        ├─ 2. флаг: <cwd>/.review.yml → solve_task.brief_token_cost == true ? иначе exit 0
        ├─ 3. атрибуция: транскрипт назад до маркера solve-task → окно ходов этапа
        ├─ 4. агрегация message.usage по 4 бакетам, с разбивкой по model
        └─ 5. вписать/заменить блок «## Токены (этап solve-task)» в файл брифа
```

Скрипт ничего не возвращает в LLM (PostToolUse advisory, `exit 0`); он мутирует **файл брифа** на диске.
Ноль доп. токенов разговора. Все ветки — **fail-open в no-op** (любая ошибка → `exit 0`, бриф не тронут).

## 4. Компоненты

Три файла; всё внутри `plugin/` (раздаётся всем пользователям плагина), кроме флага в `.review.yml` репо.

### 4.1 `plugin/hooks/hooks.json` (новый)

Декларация плагинного хука `PostToolUse` на инструмент `Write`:

```json
{
  "hooks": {
    "PostToolUse": [
      {
        "matcher": "Write",
        "hooks": [
          { "type": "command", "command": "python3 \"${CLAUDE_PLUGIN_ROOT}/hooks/brief_cost.py\"" }
        ]
      }
    ]
  }
}
```

- `matcher: "Write"` фильтрует по **имени инструмента**. Точечную фильтрацию по пути
  (`docs/superpowers/briefs/**`) делает **сам скрипт** (path-guard, §6.1) — версионно-независимо и
  надёжнее, чем полагаться на config-уровневый glob-фильтр.
- `${CLAUDE_PLUGIN_ROOT}` — документированная переменная корня плагина в команде хука.
- Подключается по конвенции плагин-хуков Claude Code (`hooks/hooks.json` в корне плагина; при
  необходимости — ссылкой `"hooks"` из `plugin/.claude-plugin/plugin.json`). Точная привязка фиксируется
  на этапе реализации согласно версии Claude Code; на поведение скрипта не влияет.

### 4.2 `plugin/hooks/brief_cost.py` (новый)

Детерминированный скрипт. Зависимости: **stdlib** + `PyYAML` (уже в окружении; при отсутствии модуля —
fail-open в no-op, §6). Не дёргает сеть, не вызывает LLM, не пишет в доску. Логика — §5–§7.

### 4.3 `.review.yml` (правка, корень репо)

Опциональный блок-флаг, дефолт **off**:

```yaml
# Дописывать в бриф solve-task расход LLM-токенов на этап (4 бакета). Считает PostToolUse-хук плагина
# по транскрипту сессии; ноль доп. LLM-токенов, без долларов. Дефолт — выключено.
solve_task:
  brief_token_cost: true
```

Читается **только хуком** (`yaml.safe_load`), server-side reviewer его игнорирует. Секретов нет.

## 5. Атрибуция окна этапа и агрегация токенов

### 5.1 Поиск окна (назад от конца транскрипта)

Транскрипт `transcript_path` (JSONL) — по строке на событие; ассистентские ходы несут
`message.usage` = `{input_tokens, output_tokens, cache_creation_input_tokens, cache_read_input_tokens}`
+ `message.model`.

- **Старт окна** = последнее **user-сообщение**, содержащее маркер запуска скилла — строку
  `Base directory for this skill:` вместе с сегментом `skills/solve-task` (надёжный маркер инвокации
  именно этого скилла). Несколько прогонов в одной сессии → берётся **последний** старт.
- **Конец окна** = конец транскрипта (момент записи брифа — последнее, что произошло).
- **Маркер не найден** → `exit 0` (no-op): нечего атрибутировать, блок не пишем.

Считаем все ассистентские ходы от старта до конца (main-loop; субагентов в этом окне нет, §2).

### 5.2 Агрегация по 4 бакетам

Для каждого хода в окне, сгруппировав **по `model`**, суммируем сырые поля транскрипта 1:1:
- `fresh-in`    += `usage.input_tokens`
- `output`      += `usage.output_tokens`
- `cache-write` += `usage.cache_creation_input_tokens`
- `cache-read`  += `usage.cache_read_input_tokens`

Никакого расщепления 5m/1h и никакой прайс-карты — это понадобилось бы только для $ (исключено, §1.1).
`model` берётся из транскрипта **как есть** (строка); заранее знать набор моделей не требуется.

## 6. Обработка ошибок (fail-open в no-op)

Любая из веток ниже → `exit 0`, **бриф не модифицируется**:

1. **Path-guard:** `tool_input.file_path` не под `docs/superpowers/briefs/` → no-op (отсекает все прочие
   `Write`). Путь нормализуется (resolve) и сверяется с briefs-директорией.
2. Нет `.review.yml` от `cwd` / нет блока `solve_task` / `brief_token_cost` ≠ `true` → no-op (дефолт off).
3. `PyYAML` не импортируется / `.review.yml` не парсится → no-op.
4. `transcript_path` нет / не читается / нет маркера solve-task → no-op.
5. Нет ассистентских ходов с `usage` в окне (нулевые токены) → no-op.
6. Файл брифа не записывается (read-only) → no-op.

Скрипт никогда не валит сессию: stderr-диагностика допустима, но код возврата всегда 0.

## 7. Формат блока в брифе и идемпотентность

Блок дописывается в конец файла брифа (или **заменяет** существующий — §7.1):

```
## Токены (этап solve-task)
Модель: claude-opus-4-8
fresh-in 9.9K · out 164K · cache-write 533K · cache-read 14.2M
Всего: 14.9M токенов
```

- Числа токенов — человекочитаемо (K/M, напр. `9.9K`, `14.2M`).
- Несколько моделей → по строке `Модель: …` + бакеты на каждую; финальное `Всего: …` — сумма всех 4
  бакетов по всем моделям окна (единый handle для сравнения «с плагином / без»).

### 7.1 Идемпотентность

Повторный прогон solve-task перезаписывает бриф целиком, затем хук срабатывает снова. Хук **заменяет**
существующий блок `## Токены (этап solve-task)` (от заголовка до конца файла или до следующего заголовка
верхнего уровня), а не дописывает второй. Если блока нет — добавляет в конец. Маркер блока — точный
заголовок `## Токены (этап solve-task)`.

## 8. Контракт stdin PostToolUse

Хук получает на stdin JSON (Claude Code PostToolUse). Используемые поля:
- `tool_name` — `"Write"` (подтверждено matcher'ом; в скрипте можно не проверять).
- `tool_input.file_path` — абсолютный путь записанного файла → path-guard (§6.1).
- `transcript_path` — путь к JSONL текущей сессии → атрибуция (§5.1).
- `cwd` — рабочая директория → поиск `.review.yml` (от `cwd`, при необходимости вверх до git-toplevel).

Имена полей сверены с документацией Claude Code (через `claude-code-guide`). Отсутствующие поля скрипт
трактует как пустые → fail-open.

## 9. Тестирование

Unit-тест на `brief_cost.py` (Python, на фейковых stdin + временном транскрипте и брифе):

1. **Флаг off / нет блока** → no-op, бриф не изменён.
2. **Флаг on + маркер solve-task** → корректный блок: 4 бакета и строка `Всего:` (проверка сумм по
   фикстуре транскрипта).
3. **Повторный прогон** (бриф уже с блоком) → блок **заменён**, не задвоен.
4. **Нет маркера solve-task** в транскрипте → no-op.
5. **Path-guard:** `Write` не в briefs/ → no-op.
6. **Смешанные модели** в окне → строка на модель, `Всего:` — сумма по всем.

Тесты — на фейках (сеть не нужна вовсе).
