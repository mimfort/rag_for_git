# PRI-236 — приёмка 0.4.5 на живом деплое + два дефекта, найденных при её подготовке

Бриф: `docs/superpowers/briefs/2026-08-11-PRI-236-acceptance-0-4-5.md`

## Проблема

Релиз 0.4.5 (PR #170) собран из четырёх задач, задевающих рантайм MCP и резолв политики: PRI-234
(fail-soft коммиченного слоя), PRI-235 (коммиченный `.review.yml` из локального клона), PRI-228
(батчи эмбеддингов по бюджету токенов), PRI-229 (сжатый `list_subsystem_clusters`). Проверка была
только unit/CI; поведение на живом деплое после `reviewer update` не проверялось.

Подготовка приёмки вскрыла два дефекта, из-за которых чек-лист задачи невыполним как написан:

1. **Критерий 1 ссылается на несуществующую опцию.** `reviewer --help` показывает единственный
   флаг `--help`; опции `--version` у CLI нет. Проверить версию можно лишь косвенно
   (`uv tool list`), то есть критерий проверяет не то, чем пользуется человек.
2. **Help-строка `--path` у `config show` противоречит реализации.** Текст обещает «по умолчанию —
   путь из индекса, затем текущий каталог», а `_resolve_clone_path` (`cli.py:196-207`) путь из
   `repo_clone` намеренно не читает — и его докстринг объясняет почему: у CLI есть cwd, а поход в
   Postgres сделал бы диагностику политики зависимой от живой БД. Ложное обещание уводит
   диагностику PRI-235 в неверную сторону: при неожиданном `committed: vcs` человек будет искать
   отсутствующую строку в `repo_clone` вместо того, чтобы проверить cwd.

## Решение

Приёмка и оба фикса делаются одной задачей. Фиксы дают PR, который сам становится объектом шага
«полный цикл ревью» — открытых PR в репозитории нет, а ревьюить смерженный PR значит писать
inline-комментарии в закрытую историю.

### 1. `reviewer --version`

`reviewer/entrypoints/cli.py`:

```python
@click.group()
@click.version_option(package_name="rag-reviewer", prog_name="reviewer")
def cli() -> None: ...
```

Click читает версию через `importlib.metadata` — тот же источник, что `versioning.detect_installation`
(`versioning.py:79`), поэтому `--version` и логика `reviewer update` не могут разойтись по
построению. Опция eager: отрабатывает до резолва подкоманды, не трогает Postgres, Neo4j и сеть.
`prog_name` задан явно — без него Click берёт имя из `sys.argv[0]`, которое при запуске через `uvx`
непредсказуемо.

Отвергнуто: кастомный callback поверх `detect_installation()` с выводом режима установки
(`0.4.5 (uv tool)`). Он дёргает `shutil.which` и `subprocess`, то есть делает самую дешёвую
диагностическую команду самой медленной, а режим установки уже печатает `reviewer update`.

### 2. Help-строка `--path`

Текст опции приводится в соответствие с `_resolve_clone_path`: «путь к локальному клону:
коммиченный `.review.yml` читается из него без сети (по умолчанию — текущий каталог)». Поведение
не меняется — меняется только обещание.

### 3. Тесты

`tests/entrypoints/test_cli.py`, unit, без инфраструктуры:

- `--version` печатает версию из метаданных пакета и завершается кодом 0;
- вывод `config show --help` не содержит обещания «путь из индекса».

Второй тест намеренно негативный. Позитивная фиксация формулировки ломалась бы при любой
редактуре текста, тогда как ловить надо ровно одно — возврат ложного обещания.

## Протокол приёмки

Прогоняется на деплое **0.4.5**, до релизного бампа: иначе это приёмка следующей версии.

| # | Шаг | Ожидаемый результат |
|---|---|---|
| 1 | `reviewer --version` | `reviewer, version 0.4.5` (после установки сборки с фиксом — `0.4.6`) |
| 2 | `reviewer check` | зелёный: ключи, Postgres, Neo4j, VCS, доска |
| 3 | `reviewer status --json` | `drift == 0` по ветке `dev`, непустые `chunks`/`graph_nodes`/`summaries` |
| 4 | `reviewer index . --ref dev` | индексация без ошибок лимита токенов Voyage (PRI-228); пишет строку в `repo_clone` |
| 5 | `reviewer config show --repo mimfort/rag_for_git --json` | `committed_source == "local"`; при запуске из каталога без клона — корректный фолбэк на `vcs` |
| 6 | `list_subsystem_clusters(compact=True, limit=10)` с пагинацией | доходит до `has_more == false`; суммарный объём страниц ≤ 12 КБ, каждая страница ≤ 4 КБ; объединённый набор `cluster_key` совпадает с непагинированным и без дублей |
| 7 | `/rag-reviewer:review-pr` на PR с фиксами | inline-комментарии и сводка опубликованы, overlay `pr:N` удалён |
| 8 | `sync_board` | инкрементально, `failed == 0`, без warnings |
| 9 | `finish_task` на PRI-236 | ссылка на PR добавлена, задача переведена в `Готово` |

Уточнения к исходным критериям задачи:

- **Критерий 1** проверяется прямой командой `reviewer --version` — ради этого и делается фикс 1.
- **Критерий 3** получает конкретные величины: `limit=10`, потолок 12 КБ на сумму страниц. Абсолютный
  порог выбран вместо отношения compact/full, чтобы не тянуть в контекст ~97 КБ полного ответа
  только ради знаменателя.
- **Ненулевой код возврата `config show`** при непустом блоке `skipped` — ожидаемое поведение
  PRI-234, а не провал приёмки.

## Порядок работ

1. Фиксы + тесты, PR в `dev`.
2. Шаги 2–9 приёмки на 0.4.5, где шаг 7 — ревью этого самого PR.
3. Мерж в `dev`.
4. Бамп версии до 0.4.6 и пересборка codex-манифестов (изменение `version` меняет payload-digest).
5. PR `dev` → `main`, мерж.
6. После `reviewer update` пользователем — повторный прогон шагов 1–5 на 0.4.6 как проверка
   доставки.

## Что вне скоупа

- Вывод режима установки в `--version`.
- Чтение `repo_clone` в CLI: поведение корректно и обосновано, правится только его описание.
- Ретрофит httpx-обвязки старых board-адаптеров и прочий долг, не затронутый релизом.
