# PRI-163 — solve-task: персист solution brief в артефакт

**Дата:** 2026-06-25
**Слой:** Плагин/скил `solve-task` — надёжность/трассируемость.
**Оценка:** S.
**Связи:** PRI-146 (спека brief + relevance-фильтр); артефакты superpowers SDD (`docs/superpowers/{specs,plans}/`).

## Проблема

SDD-флоу персистит спеки и планы в `docs/superpowers/{specs,plans}/` (файлы закоммичены в git,
формат имени `ГГГГ-ММ-ДД-<имя>.md`). Скил `solve-task` же распиливает solution brief (шаг 4
«Distill») и отдаёт его в `superpowers:brainstorming` **только в контексте разговора**
(`plugin/skills/solve-task/SKILL.md:170`, шаг 5 «Show the brief, then invoke
superpowers:brainstorming»). После компакта контекста / в новой сессии бриф испаряется — рвётся
трасса задача→бриф→спека→план→PR.

## Цель

После шага 4 (Distill) и до хендоффа `solve-task` сохраняет бриф файлом в новую папку
`docs/superpowers/briefs/`, а шаг 5 ссылается на путь к этому файлу. Бриф переживает компакт
контекста / новую сессию и становится первым звеном трассы; board-less режим тоже сохраняется.

Объём — **минимальный персист** (YAGNI): трасса мягкая (ключ задачи в имени/теле файла, связь
грепом по ключу). Жёсткие перекрёстные ссылки бриф↔спека↔план в скоуп НЕ входят.

## Решение

Правки только в `plugin/skills/solve-task/SKILL.md` (шаги 4–5) + guard-тест в `tests/skills/`;
опционально — упоминание папки `briefs/` в README/CLAUDE.md.

### 1. Куда вставить (SKILL.md, без перенумерации)

- Инструкция персиста — **финальным абзацем шага 4** (сразу после текущей строки 168
  «Cite `path:line` straight from the line-numbered Step 3 snippets…»). Новый top-level шаг НЕ
  вводим: это сломало бы внутренние кросс-ссылки («Step 4 filter» @124/127, «Step 3 contract»
  @168) и потребовало бы сдвига номеров.
- **Шаг 5 (Hand off)** дополняется: показать бриф → назвать сохранённый путь → инвокировать
  `superpowers:brainstorming`, **передавая путь к файлу** как seed/контекст (а не только текст
  в контексте, который не переживёт компакт).

### 2. Папка, имя файла, идемпотентность

- Новая папка `docs/superpowers/briefs/`. **Коммитим** (как specs/plans — оставляем след;
  `.gitignore` игнорит только `.superpowers/`, briefs под игнор не попадает).
- **С ключом задачи:** `ГГГГ-ММ-ДД-<KEY>-<slug>.md`, где
  - `KEY` — пользовательский ключ доски (под `key_pattern`, напр. `PRI-163`), не нормализованный
    store-ключ (`ID-163`);
  - `slug` — короткий ASCII-kebab из тайтла задачи (транслитерация/сжатие до ~4–6 слов).
  - Пример: `2026-06-25-PRI-163-persist-solution-brief.md`.
- **Board-less режим (нет ключа):** `ГГГГ-ММ-ДД-<slug>.md`, slug — kebab из формулировки
  пользователя. Пример: `2026-06-25-add-logout-endpoint.md`.
- **Дата** — сегодняшняя в ISO (`ГГГГ-ММ-ДД`).
- **Идемпотентность:** перед записью — glob `docs/superpowers/briefs/<дата>-<KEY>-*.md`; при
  совпадении перезаписать найденный файл (slug-дрейф между прогонами не плодит дубли). Board-less —
  точное имя `<дата>-<slug>.md`.

### 3. Содержимое файла

Ровно распиленный бриф по существующему скелету (`# Brief — <KEY> <title>` + секции Task /
Related work / Subsystems / Relevant code / Constraints). При наличии — строкой ниже заголовка
URL задачи (самоописание + грепабельность по ключу). Без дополнительной обвязки.

### 4. Fail-open

Персист — best-effort: если запись не удалась (read-only ФС, нет прав и т.п.) — нота в хендоффе,
и скил всё равно хендоффит с in-context брифом. Никогда не abort — консистентно с остальным
fail-open поведением скила. Ноту «Read-only on the board; this skill never writes to it»
оставляем (она про доску), рядом уточняем: единственная запись скила в репозиторий — файл брифа.

### 5. Guard-тест

В `tests/skills/test_solve_task_brief.py` добавить `test_solve_task_persists_brief()` —
маркер-проверки текста `SKILL.md` (не пинят точные формулировки, в стиле существующих guard-ов):

- присутствует целевой путь `docs/superpowers/briefs/`;
- присутствует глагол/маркер персиста (бриф сохраняется файлом);
- шаг 5 (хендофф) ссылается на путь к файлу брифа;
- упомянут board-less slug (сохранение и без ключа).

### 6. Docs (опционально)

Одна строка про `docs/superpowers/briefs/` рядом с упоминанием specs/plans в README или CLAUDE.md —
если найдётся естественное место; иначе пропустить (в задаче помечено «опц.»).

## Критерии приёмки

- После `solve-task` бриф лежит файлом по предсказуемому пути в `docs/superpowers/briefs/`.
- Хендофф в `brainstorming` ссылается на путь к файлу.
- Бриф переживает компакт контекста / новую сессию; board-less режим тоже сохраняется.
- Повторный прогон того же ключа в тот же день не плодит дубли (идемпотентность по префиксу).
- Guard-тест на наличие шага персиста зелёный; весь `tests/skills/` без регрессий.

## Затрагиваемые файлы

- `plugin/skills/solve-task/SKILL.md` — шаги 4–5 (персист + ссылка на путь в хендоффе; уточнение
  ноты про запись в репо).
- `tests/skills/test_solve_task_brief.py` — новый guard-тест `test_solve_task_persists_brief()`.
- `docs/superpowers/briefs/.gitkeep` (или первый реальный бриф) — чтобы папка существовала в репо.
- (опц.) `README.md` / `CLAUDE.md` — одна строка про `briefs/`.

## Вне скоупа

- Жёсткие перекрёстные ссылки бриф↔спека↔план (правки чужих скилов brainstorming/writing-plans).
- Любые изменения логики сбора контекста (шаги 0–3) и формата самого брифа (скелет из PRI-146).
- Автоматическая чистка/ротация старых брифов.
