# PRI-299. Структурированные ссылки брифа

Бриф задачи — `docs/superpowers/briefs/2026-11-21-PRI-299-structured-brief.md`.

Модель формирует записи `section`, `path`, `line`, `reason` и необязательную роль `edit` или `read`. Единый список идёт от исполнителя к оркестратору и затем в `verify_task_brief` по тому же MCP-соединению, на котором выдан идентификатор контекста. Модель сохраняет порядок выдачи и выбирает только нужные для реализации ссылки. Роль дополняет пояснение и не влияет на отбор, подтверждение или метрику.

Вызов с `references` проверяет те же полностью видимые строки, что и действующий вызов с `citations`. Входы взаимоисключающие. Задокументированный результат `citations` сохраняет вердикты и переданные поля. При наличии идентификатора результат содержит `render_status` и `markdown`. `ok` означает успешный рендер, `empty` обозначает отсутствие подтверждённых записей, `invalid_format` означает невозможность безопасного рендера или расхождение при обратном чтении. Для `invalid_format` Markdown отсутствует и клиент может исправить записи и повторить вызов. Для `empty` возвращается валидная секция `## Relevant code` без ссылок. Для утраченного идентификатора действует существующий `evidence_unavailable`. Записи старых вызовов и их ответы сохраняют прежний формат.

Сервер рендерит существующие заголовки и по одной Markdown-строке на подтверждённую запись. Секция с результатом сервера имеет служебную HTML-метку. Путь и строка находятся в начале пункта внутри Markdown-кода. Пояснение занимает одну строку и может упоминать другие файлы. Метка роли видна в пояснении. Порядок ссылок внутри секций сохраняется. Перед возвратом сервер читает точные тройки `section/path/line` и сверяет их с подтверждёнными записями. Метрика читает ссылки помеченных секций по тому же формату, а для старых секций сохраняет исторический разбор с поддержкой префиксов «Править» и «Прочитать». Старая проверка Claude Code оставляет секции с серверной меткой без изменений.

Совместимый клиент копирует блок Markdown без изменений и сверяет его после записи файла. Заметки об отброшенных результатах можно вынести в ограничения. На старом сервере с идентификатором выдачи клиент сохраняет подтверждённые записи по результату проверки `citations`. Если идентификатор недоступен, применяется ручная сверка по исходным видимым строкам. В обоих случаях используются привычные заголовки без серверной метки.

Приёмка охватывает обе секции, исторические формы ссылок, ссылку за границей показанного фрагмента и за пределами секции, роль в пояснении, незачтённое упоминание в причине, валидную пустоту и нечитаемый формат. Реальный smoke в Codex и Claude Code должен передать одинаковые записи через MCP и прочитать сохранённый Markdown. Пилот использует прежние шесть задач, точные входные фрагменты и файловый лимит 20, Luna low и два повторения. Для каждой задачи считаются покрытие размеченного ядра, покрытие зависимостей и ошибки формата. Эффект роли отдельно не оценивается.
