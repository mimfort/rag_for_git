# Дизайн — PRI-252: расхождение числа рёбер SCIP-графа

Происхождение: `docs/superpowers/briefs/2026-08-14-PRI-252-scip-graph-edge-count-regression.md`

## Установленная причина (воспроизведена, не гипотеза)

Все замеры ниже сделаны на одном коммите `b911c52`, одном наборе входа (498 файлов,
7270 узлов графа), меняется ровно одна переменная — Python-окружение, унаследованное
процессом `reviewer index`. `run_scip_python` запускает `scip-python` с `cwd=<временный
worktree>`, а worktree — голый чек-аут без своего окружения, поэтому резолвинг типов
pyright определяется окружением запускающего процесса.

| Условие запуска | CALLS | IMPLEMENTS |
|---|---|---|
| `.venv` проекта (editable-установка) | 30254 | 129 |
| без venv (системный python) | 32832 | 129 |
| `uvx --from rag-reviewer` | 34158 * | — |

\* для `uvx` измерено суммарное число рёбер (34287) выводом самой команды; CALLS получен
вычитанием IMPLEMENTS, инвариантных в двух измеренных напрямую условиях.

Внутри каждого условия результат детерминирован (повторные прогоны совпали до ребра —
проверено для `.venv` и для `uvx`). То есть «недетерминизм» из описания задачи — это
на самом деле три разных условия запуска, а не случайность.

Но настоящая причина расхождения лежит глубже, и она — дефект `parse_scip`, а не
окружения. Раскладка CALLS-рёбер по классу символа callee:

| Класс символа callee | `.venv` | без venv | расхождение |
|---|---|---|---|
| `repo` — настоящие межсимвольные ссылки | 17776 | 17683 | 0.5 % |
| `local N` — нерезолвленные/файл-локальные имена | 12479 | 15150 | 21 % |

`local N` — идентификатор символа SCIP, **уникальный только внутри документа**:
`local 5` в `reviewer/app.py` и `local 5` в `tests/web/test_pool.py` — это строчно
один и тот же ключ. `parse_scip` кладёт все definition-символы в один глобальный
`symbol_to_node`, поэтому документы перетирают друг друга, и ссылка на локальное имя
в одном файле резолвится в определение из совершенно другого файла. Отсюда рёбра вида:

```
reviewer/app.py#_close_resources  --CALLS-->  tests/web/test_pool.py#test_history_creates_pool_lazily_with_sizes
```

Таких фиктивных рёбер `reviewer/* → tests/*` в текущем графе **14942 из 30254 —
49 %**. Чем хуже окружение резолвит типы, тем больше символов остаются `local`, тем
больше фикции, тем больше «рёбер» — то есть наблюдавшийся рост числа рёбер был ростом
мусора, а падение — его убылью. Полнота настоящего графа при этом не колебалась: 17683
против 17776, 0.5 %.

Побочно закрыт второй вопрос описания: IMPLEMENTS инвариантны к окружению (129 в обоих
условиях) и раскладываются как SCIP 121 + tree-sitter 82 при пересечении 74. Цифра «327»
из спеки PRI-251 в текущих условиях не воспроизводится ни в одном окружении; она не
относится к расхождению между прогонами и в скоуп этой задачи не входит.

## Решение

Четыре компонента, по одному на критерий приёмки.

### A. Скоупинг `local`-символов по документу (корень)

В `reviewer/graph/scip.py::parse_scip` разделить карту символов: глобальные символы
(моникер с менеджером пакетов) остаются в общем `symbol_to_node`, символы вида
`local <N>` живут в `local_by_doc[relative_path]`. При построении рёбер класс символа
выбирает карту: `local` резолвится только внутри своего документа. Та же логика
применяется к `SymbolInformation` при построении IMPLEMENTS.

Рассматривались два варианта: полностью отбрасывать `local`-символы (17776 / 17683 рёбер)
и скоупить их по документу (18092 / 17999). Выбран скоупинг: он не теряет корректные
внутрифайловые рёбра (вложенные функции, лямбды — +316 рёбер к варианту с отбрасыванием)
и при этом полностью убирает кросс-файловую фикцию. Расхождение между окружениями падает
с 8.5 % до 0.5 %; фиктивных рёбер `reviewer/* → tests/*` становится 0.

### B. Разбивка рёбер по типам в выводе (критерий 2)

Новый модуль `reviewer/graph/metrics.py` с чистыми функциями — без БД, без Neo4j,
тестируется юнитами:

- `count_edges_by_rel(edges) -> dict[str, int]` — счётчики по типу ребра;
- `detect_edge_regression(prev, curr, threshold) -> list[str]` — человекочитаемые
  сообщения о просадке.

`reviewer index` печатает разбивку в той же строке итога:

```
граф [scip]: узлов 7270, рёбер 18092 (CALLS 17963, IMPLEMENTS 129)
```

### C. Просадка полноты не проходит молча (критерий 3)

Счётчики предыдущего прогона той же ветки персистятся, текущие сравниваются с ними.

- **Хранилище:** `index_meta` — таблица уже ключуется `(repo, ref)`, то есть per-ветка,
  и уже переживает апгрейды. Добавляется nullable колонка `graph_edges jsonb`.
  Миграция аддитивная и идемпотентная (`ADD COLUMN IF NOT EXISTS`) — принятый в проекте
  стиль; отсутствие колонки (индекс старой версии) читается как «предыдущего замера нет».
- **Store:** два новых метода — `set_graph_edge_counts(repo, ref, counts)` и
  `get_graph_edge_counts(repo, ref) -> dict | None`. Счётчики пишутся отдельным методом,
  а не параметром `set_index_meta`: SHA записывается до построения графа, а счётчики
  известны только после него. Чтение возвращает `None` при
  `UndefinedTable`/`UndefinedColumn`/отсутствии записи — тем же fail-soft способом, что
  уже применяют `get_index_meta` и `get_index_meta_row`.
- **Порог:** просадка типа рёбер более чем на 10 % от предыдущего замера той же ветки, а
  также полное исчезновение ранее присутствовавшего типа. Порог — константа модуля
  `metrics.py`, env-слоя не заводим (тот же выбор, что у `context_limits`).
- **Поведение:** предупреждение печатается в stdout команды и уходит в `log.warning`;
  команда не падает. Критерий требует, чтобы просадка не прошла молча, а не чтобы
  индексация сломалась — граф к этому моменту уже записан, и отказ оставил бы
  пользователя без индекса и без информации.
- **Порядок:** счётчики читаются ДО записи новых (иначе сравнивать не с чем) и
  записываются вместе с SHA.

### D. Факт в CLAUDE.md (критерий 4)

В блок «Граф кода — два бэкенда» добавляется неочевидный факт из двух частей:
`local N`-символы SCIP файл-скоупные (глобальная карта давала кросс-файловую фикцию —
половину CALLS-рёбер), и остаточная зависимость числа рёбер от окружения запуска
`scip-python` (~0.5 %) — причина, по которой у детектора просадки есть порог, а не
проверка на равенство.

## Тестирование

- unit `parse_scip`: два документа с одинаковым `local 0` не порождают ребра между собой
  (регрессионный тест ровно на этот дефект); `local`-символ внутри одного документа
  ребро порождает.
- unit `count_edges_by_rel` и `detect_edge_regression`: порог, исчезнувший тип,
  отсутствие предыдущего замера, рост (не просадка).
- unit вывода `reviewer index`: разбивка по типам печатается; при просадке печатается
  предупреждение и команда завершается успешно.
- integration (store): миграция идемпотентна, round-trip счётчиков, чтение при
  отсутствующей колонке даёт `None`.
- integration (граф, `skipif` без `scip-python`): на мини-репо из двух файлов с
  одноимёнными локальными переменными кросс-файловых рёбер нет.

## Влияние и риски

- Число рёбер графа падает примерно на 41 % (34287 → ~18100) — это удаление фикции, а не
  потеря полноты; graph-expansion в ретриве и blast-radius перестают тянуть случайные
  тесты к продовым символам.
- Первый прогон после апгрейда сравнит новые счётчики со старыми и напечатает
  предупреждение о просадке. Это одноразово и ожидаемо; упомянуть в CHANGELOG при релизе.
- Граф в Neo4j перестраивается целиком при `reviewer index`, отдельная миграция графа не
  нужна.

## Вне скоупа

- Изоляция окружения `scip-python` (установка зависимостей в worktree, фиксированный
  интерпретатор). После фикса A остаточная зависимость — 0.5 %, цена изоляции этого не
  оправдывает; факт задокументирован, детектор просадки её покрывает порогом.
- Расхождение «129 против 327 IMPLEMENTS» из спеки PRI-251: IMPLEMENTS инвариантны к
  окружению, к расхождению между прогонами отношения не имеют.
- Ретрофит `self-heal` графа (`services/graph_sync.py`) — он строит граф tree-sitter'ом,
  дефекта `local`-символов там нет.
