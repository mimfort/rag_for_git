# PRI-154 — `read_file` skeleton-режим (AST-скелет → полное тело по запросу)

**Задача:** PRI-154 / ID-154. Слой: движок (MCP-тул `read_file`) — экономия токенов.

## Проблема

При итеративной навигации субагент ревью многократно тянет полные тела файлов через
`read_file`. Для первичной ориентации достаточно скелета: список определений
(`def`/`class`), их сигнатуры и первая строка docstring. Полное тело нужно лишь точечно,
последующим `read_file(path, start, end)`.

## Решение

Добавить опцию `skeleton: bool = False` в `read_file`. При `skeleton=True` тул отдаёт
AST-скелет файла вместо полного тела: модульный docstring (1-я строка) + декораторы и
сигнатуры всех `def`/`class` (включая вложенные и многострочные — до `:`) + первая строка
docstring каждого определения. Вывод — те же нумерованные строки `N|код`, что и у обычного
режима; разрывы в номерах строк сами сигналят об опущенных телах (без отдельных `…`-маркеров —
минимум токенов).

### Компоненты

1. **`reviewer/index/chunker.py` — новая чистая функция `python_skeleton(source: bytes) -> list[int]`.**
   Переиспользует `_PARSER`/`_PY` (tree-sitter-python). Возвращает отсортированный список
   уникальных 1-based номеров строк, входящих в скелет:
   - модульный docstring — первая физическая строка (если есть);
   - для каждого `function_definition`/`class_definition` (с учётом `decorated_definition`,
     вложенность как в `chunk_python`): строки заголовка от начала (включая декораторы) до
     строки с `:` перед телом — находим `:`-токен среди детей определения; затем первая строка
     docstring тела (если первый statement тела — строковый литерал).
   - Синтаксические ошибки/нетипичный источник не роняют функцию (как `chunk_python`).
   Рендеринг и кап остаются в `read_file` — функция не знает про формат `N|`.

2. **`reviewer/tools/code_tools.py` — `read_file(path, start=1, end=400, skeleton=False)`.**
   При `skeleton=True`: `lines = python_skeleton(src.encode("utf-8"))`; `start/end` игнорируются
   (скелет — обзор всего файла). Рендер только этих строк как `N|код` (исходная индентация
   сохраняется естественно — берём оригинальные строки). Кап: если строк скелета > 400 —
   усечь до 400 + `\n(…усечено)`. **Фолбэк:** если `python_skeleton` вернул пусто (не-Python /
   только модульный код без определений) — вернуть обычный нумерованный срез `[start..end]` с
   однострочной заметкой-префиксом `(нет определений для скелета — полный фрагмент)`, чтобы
   агент не тратил лишний раунд. Полный режим (`skeleton=False`) не меняется.

3. **`reviewer/mcp/service.py` — `read_file(self, repo, pr, path, start=1, end=400, skeleton=False)`.**
   Протянуть `skeleton` в `_invoke_tool(..., {"path":path,"start":start,"end":end,"skeleton":skeleton})`.

4. **`reviewer/entrypoints/mcp_server.py` — обёртка `read_file(repo, pr, path, start=1, end=400, skeleton=False)`.**
   Добавить `skeleton` в сигнатуру + докстринг (упомянуть skeleton-режим: компактный обзор,
   полное тело — последующим вызовом с диапазоном). Передать в `service.read_file`.

### Поток данных

`mcp_server.read_file(..., skeleton)` → `service.read_file(..., skeleton)` →
`_invoke_tool("read_file", {...,"skeleton":...})` → `make_tools(ctx)` пересоздаёт тул →
`code_tools.read_file(..., skeleton)` → при skeleton: `python_skeleton(bytes)` →
рендер выбранных строк.

### Обработка ошибок / краевые случаи

- read_file_fn недоступен / файл не найден / пуст — как сейчас (skeleton не доходит до парсинга).
- Не-Python или файл без определений — фолбэк на обычный срез + заметка.
- Синтаксически битый Python — tree-sitter парсит частично; функция отдаёт что смогла, не падает.
- Многострочные сигнатуры — заголовок целиком (до `:`).
- Однострочный `def f(): ...` — `:` на той же строке, в скелет попадёт вся строка (редкий случай, приемлемо).
- Кэш `_memoize` ключует по аргументам (включая `skeleton`) — skeleton/полный режим кэшируются раздельно, проблем нет.

### Тестирование

- `tests/index/test_chunker.py` (или новый `test_skeleton.py`): `python_skeleton` —
  извлекает заголовки top-level и вложенных def/class; включает декораторы; первую строку
  docstring; модульный docstring; не падает на битом источнике; пусто для источника без определений.
- `tests/tools/test_code_tools.py`: `read_file(skeleton=True)` — содержит сигнатуры, не содержит
  строк тела; полный режим без изменений; фолбэк на источнике без определений; кап на 400.
- `tests/mcp/test_service.py` / `tests/entrypoints`: проброс `skeleton` через слои (по месту,
  по существующим конвенциям guard-тестов).

## Не делаем (YAGNI)

- Не вводим skeleton для session-less Q&A-тула (его нет; задача — про PR-сессию `read_file`).
- Не делаем `…`-маркеры тел (разрывы номеров строк достаточны).
- Не поддерживаем не-Python языки (целевой язык анализа — Python).
- skeleton не комбинируется с `start/end` (обзор всегда по всему файлу).
