# Global Client Install Lifecycle Design

## Goal

Make `reviewer install --all` reliably configure every detected supported
client from any working directory. Native plugin clients receive their native
global lifecycle; config-only clients retain their documented client-specific
MCP formats and optional file skills.

## Scope

The supported client set is the `CLIENTS` registry in `reviewer/install.py`:
Cursor, Claude Desktop, Claude Code, VS Code, Windsurf, Gemini CLI,
Antigravity, Mimo Code, OpenCode, Kimi Code, Trae IDE, and Codex CLI.

Codex remains on its existing specialised installer. Claude Code gains a
parallel specialised installer. The remaining clients continue to use the
generic config-plan path; this change adds a complete registry-level contract
test rather than inventing unsupported plugin lifecycles for them.

## Claude Code Contract

`reviewer install claude-code` and `reviewer install --all` when the `claude`
executable is available use user scope and perform this lifecycle:

1. Check that the installed Claude CLI supports marketplace add/list and
   plugin install/list JSON output.
2. Add or refresh marketplace `rag-reviewer-marketplace` from the canonical
   HTTPS source `https://github.com/mimfort/rag_for_git.git`, with sparse paths
   `.claude-plugin` and `plugin`.
3. Install `rag-reviewer@rag-reviewer-marketplace` at user scope.
4. Verify the marketplace source is canonical and the plugin is installed and
   enabled using the CLI JSON state.
5. Ensure the global Claude Code allowlist contains `mcp__reviewer__*`.

The HTTPS source is mandatory: Claude's GitHub shorthand chooses SSH on the
current CLI and would fail for users without SSH credentials.

The bundled `plugin/.mcp.json` must use direct `uvx` argv instead of
`/bin/bash -lc`, so the plugin's MCP server is portable to Windows, macOS, and
Linux.

`--no-skills` does not install or update the Claude plugin. It instead uses
the official `claude mcp add --scope user` path to configure the global
`reviewer` stdio server and writes the same allowlist. `--dry-run` only shows
the intended Claude commands and configuration changes; it does not invoke
network-backed marketplace commands or write state.

If Claude is explicitly requested but unavailable or lacks a required
capability, the command fails with an actionable error. In `--all`, a Claude
failure is collected and reported after the independent generic clients have
been processed, matching the existing Codex error behaviour. No command may
report a successful Claude installation until its post-install state verifies.

## Generic Client Contract

For every detected non-native client, `reviewer install --all` must write one
`reviewer` MCP entry in that client's documented dialect and retain unrelated
configuration. The launch command and arguments are generated by
`launch_command()` and must be represented correctly in each dialect:

- standard JSON `mcpServers` clients use `command` plus `args`;
- VS Code uses `servers`;
- Mimo and OpenCode use their local command-array forms;
- Codex uses its specialised TOML/plugin lifecycle.

Gemini, Mimo, OpenCode, and Kimi additionally receive their global file-based
skills unless `--no-skills` is supplied. Re-running the command must not add a
second reviewer entry or corrupt unrelated keys.

## Safety and Error Handling

All real-client testing uses temporary `HOME`, `CODEX_HOME`, and
`CLAUDE_CONFIG_DIR`; no test changes a developer's live profile. The installer
uses only the documented public CLI commands. It verifies each native CLI
mutation from fresh public CLI state: JSON where the CLI offers JSON, and the
documented human-readable `claude mcp get reviewer` output for Claude's
MCP-only mode, whose command has no JSON option. It never parses private cache
files.

The Claude CLI owns its marketplace/cache mutation. The reviewer wrapper does
not delete a marketplace or plugin on a failed update because the public CLI
does not offer an exact transaction restore; instead it stops with the phase,
argv, and CLI error and never masks that failure as a successful `--all` run.
The generic config writer continues to make byte backups before changes.

## Tests and Acceptance Criteria

Unit tests use a file-backed fake Claude runner for fresh install, repeat
install, foreign/unusable state, failure propagation, dry run, and post-install
verification. CLI dispatch tests prove that explicit `claude-code` and
detected `--all` select the specialised lifecycle without creating a
project-local `.mcp.json`.

A registry-level generic install test creates all supported config parents in
a temporary profile, invokes `--all`, parses every written config, and checks
exactly one correct reviewer entry plus expected skills locations. Existing
client-specific tests remain as format-level coverage.

The repository's current Ruff baseline is repaired with small
behavior-preserving formatting/import cleanups in the affected production and
test files. Final acceptance requires `uv run ruff check .` to pass, rather
than suppressing or reporting those pre-existing violations.

The final acceptance check runs the real Claude and Codex CLIs from an outside
directory with fresh temporary profiles. It verifies an enabled
`rag-reviewer@rag-reviewer-marketplace`, an enabled
`rag-reviewer@rag-reviewer` Codex plugin, and their MCP registrations.
