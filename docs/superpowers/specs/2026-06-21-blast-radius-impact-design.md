# Дизайн: Анализ радиуса поражения по графу (blast-radius)

- **Задача:** PRI-126 / ID-126 «12. Анализ радиуса поражения по графу ★» (оценка M)
- **Дата:** 2026-06-21
- **Ветка:** dev
- **Колонка доски:** Плагин/агент (скилы)

## Контекст и проблема

Ревью PR идёт через per-file fan-out: каждый субагент видит **один** изменённый файл.
Поэтому смена сигнатуры функции в файле A, ломающая её вызывающих в файлах B/C/D
(не затронутых диффом), **систематически недодетектируется** — ни один субагент не владеет
кросс-файловым контекстом контракта.

Граф кода уже хранит входящие рёбра `CALLS` и умеет `callers()` / `expand()` /
`symbols_for_paths()` (`reviewer/graph/store.py`). Не хватает измерения, которое возьмёт
изменённые символы PR, найдёт их вызывающих **вне диффа** и выдаст находки о возможных
поломках контракта.

### Что уже есть (не делаем заново)

- `reviewer/graph/store.py::callers()` (`store.py:86`) — входящие `CALLS`.
- MCP-тул `find_callers(repo, pr, node_id)` — гранулярный примитив (1 символ → bare `path#fqn`).
- `changed_node_ids` / `changed_paths` / `patches` доступны в PR-сессии (`ToolContext`).
- Категория `correctness` уже в схеме находок (`analyze-prompt.md:86`) — схему не меняем.

### Чего реально не хватает (ценность задачи)

1. Агрегация **всех** изменённых символов разом + обогащение вызывающих сигнатурой/строкой/сниппетом.
2. «Сигнатурный гейт» — отсечь чисто внутренние рефакторинги (тело поменяли, контракт нет).
3. Выделенное **обязательное** измерение blast-radius в пайплайне review-pr.

## Цель и критерий приёмки

**Цель:** ловить кросс-файловые поломки контракта при смене сигнатуры.

**Критерий приёмки (из задачи):** PR, меняющий сигнатуру функции с N вызывающими, даёт находку
по необновлённым местам.

## Принятые решения

1. **Глубина детекции — сигнатурный гейт + LLM.** Движок даёт факты: вызывающие вне диффа +
   old/new сигнатура изменённого символа. Вердикт «сломано ли» — за LLM-измерением. (Не минимальная
   эвристика — шум; не точный парсинг арности call-site — L, хрупко на `*args`/`**kwargs`/keyword-only.)
2. **Новый тул `get_impact`** — `find_callers` остаётся гранулярным примитивом; `get_impact`
   высокоуровневый (без аргументов берёт `changed_node_ids` сессии, возвращает структурированный
   отчёт). Разная семантика → два тула оправданы; не перегружаем `find_callers` (его используют
   analyze/verify-промпты).
3. **Отдельный whole-diff субагент** — blast-radius встраивается в шаг 4 SKILL.md (рядом с
   performance/maintainability/requirements), не в per-file analyze (это ровно та проблема, что
   задача решает).

## Архитектура и поток данных

`get_impact()` — PR-сессионный тул без аргументов (контекст берётся из сессии):

```
changed_node_ids (символы изменённых файлов)
   │
   ├─ old = store.fetch_nodes_at(repo, ids, base_ref(branch))     # версия ДО PR
   ├─ new = store.fetch_nodes_at(repo, ids, overlay_ref="pr:N")   # версия В PR
   │
   ▼  СИГНАТУРНЫЙ ГЕЙТ: extract_signature(old.text) != extract_signature(new.text)
   gated_symbols  (только символы с реально изменённым def-заголовком)
   │
   ├─ для каждого: graph.callers(repo, [node_id], branch)          # входящие CALLS
   ├─ фильтр: path вызывающего ∉ changed_paths                     # «вне диффа»
   └─ обогащение: store.fetch_nodes(...) → path:line определения + сниппет заголовка
   │
   ▼
структурированный текстовый отчёт:
  symbol#fqn:  old_sig → new_sig
    устаревшие вызывающие (вне диффа):
      - path:line  | заголовок вызывающего символа
```

- Гейт в **движке** отсекает не-сигнатурные изменения → нет шума на всех вызывающих.
- **LLM** решает, ломает ли смена контракта конкретного вызывающего, и пишет находку `correctness`.
- Символы добавленных файлов (нет base-версии) → нет old-сигнатуры → пропускаются (у новой функции
  нет существующих вызывающих).

## Компоненты

### Движок — новый модуль `reviewer/tools/impact.py`

Чистая логика, тестируемая на фейках без БД:

- `extract_signature(node_text: str) -> str | None` — выдёргивает заголовок
  `def`/`async def`/`class` (от ключевого слова до закрывающей `:`), схлопывая пробелы; корректен
  для многострочных сигнатур по балансу скобок. `None`, если заголовок не найден.
- `compute_impact(graph, store, *, repo, branch, changed_node_ids, changed_paths, overlay_ref) ->
  list[ImpactItem]` — реализует поток выше (гейт → callers → фильтр вне диффа → обогащение).
- `ImpactItem` (dataclass): `{node_id, old_sig, new_sig, callers: list[CallerRef]}`;
  `CallerRef`: `{node_id, path, line, snippet}` — `line` = строка определения вызывающего символа,
  `snippet` = его заголовок (рёбра `CALLS` символ→символ, не line-precise call-site).
- Форматтер отчёта в строку для MCP-вывода (по образцу существующих тулов).

### Стор — `reviewer/index/store.py`

- Добавить `fetch_nodes_at(repo, node_ids, ref) -> list[Retrieved]` — выборка текста чанка по
  **конкретному** ref (без слияния base/overlay). Зеркало `fetch_nodes` с `WHERE c.ref=%(ref)s`.
  Нужно для отдельного взятия base-версии изменённого файла (old-сигнатура): в обычном `fetch_nodes`
  base-строки изменённых путей исключаются правилом свежести.

### Граф — `reviewer/graph/store.py`

Без изменений: `callers()` переиспользуется как есть.

### Тул (3 слоя по конвенции проекта)

- `reviewer/tools/code_tools.py::make_tools` — замыкание `get_impact()` (без аргументов; берёт
  `ctx.graph/store/changed_node_ids/changed_paths/overlay_ref/branch/repo`, вызывает
  `compute_impact`), добавить в список `raw`.
- `reviewer/mcp/service.py` — `get_impact(repo, pr)` → `_invoke_tool(repo, pr, "get_impact", {})`.
- `reviewer/entrypoints/mcp_server.py` — `@mcp.tool() def get_impact(repo, pr) -> str`.

### Агент (плагин)

  субагент) в список dimensions; выдаёт находки `category=correctness`.

## Inline-ограничение GitHub и якорение находки

Устаревшие вызывающие лежат в файлах **вне диффа** → GitHub запрещает там inline-комментарии
(`assemble` увёл бы находку в сводку). Чтобы находка была inline-полезной, blast-radius-промпт
инструктирует:

- **якорить находку на строку изменённой сигнатуры** (`def`-строка в RIGHT-части диффа —
  commentable; `code_quote` = новый заголовок, проходит grounding);
- **список устаревших вызывающих** (`path:line`) перечислять в **теле** сообщения.

Итог: комментарий садится inline на изменённый `def`, тело — «N вызывающих не обновлены под новую
сигнатуру: …».

## План тестирования

**Unit (`pytest -q`, на фейках):**

- `extract_signature` — одно/многострочные сигнатуры, `async def`, декораторы, `class`, идентичные
  заголовки (гейт молчит).
- `compute_impact` — фейк-граф (`callers`) + фейк-стор (`fetch_nodes_at`/`fetch_nodes`):
  - гейт отсекает не-сигнатурные изменения;
  - вызывающие внутри диффа (`path ∈ changed_paths`) отфильтрованы;
  - обогащение содержит `path:line` определения вызывающего + сниппет заголовка;
  - **сценарий критерия приёмки:** сигнатура с N вызывающими вне диффа → отчёт перечисляет
    необновлённые места.
- Регистрация `get_impact` в `make_tools` (как существующие тесты `code_tools`).

**Integration (`-m integration`, нужен ParadeDB):**

- `fetch_nodes_at` рядом с тестами `store` (реальная выборка по ref).

## Известные ограничения (документируем, без доп. работы)

- Recall вызывающих в живом ревью зависит от инкрементального **tree-sitter**-графа (CALLS по
  имени, repo-scoped); полный SCIP (точные CALLS+IMPLEMENTS) — только ручным `reviewer index`.
  Промпт формулирует находки как «потенциально устаревшие» и просит LLM подтвердить через `read_file`.
  Это риск из самой задачи, не регресс.
- Гейт по def-заголовку ловит изменения арности/имён/дефолтов параметров; не ловит изменения
  семантики при неизменной сигнатуре (это и не цель — там нет контрактной поломки на уровне вызова).

## Вне скоупа

- Точное сравнение арности call-site (парсинг аргументов вызова).
- Принудительный SCIP-синк графа в `prepare_review`.
- Рёбра `IMPLEMENTS` для blast-radius (только `CALLS`).
- Поддержка не-Python языков.
