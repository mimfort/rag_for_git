# Удаление сервиса `web` из docker-compose

**Дата:** 2026-06-21
**Тип:** инфраструктура + документация (Python-код не затрагивается)

## Проблема

При `docker compose up` на свежем клоне репозитория сервис `web` тянет тяжёлую
многоступенчатую сборку фронтенда (`web/Dockerfile`: `node:20-alpine` → `npm ci` +
`npm run build`, затем `python:3.12-slim` + pip install). У тех, кто просто хочет
поднять инфраструктуру (Postgres/ParadeDB + Neo4j), эта сборка падает/висит и не нужна.
Веб-админка наблюдаемости — опциональная dev-фича, не обязательная для работы ревьюера.

## Решение (скоуп)

Удалить **только** docker-compose-сервис `web`. Сама фича наблюдаемости остаётся живой
и доступной на хосте через `reviewer serve` (CLI). Никакой Python-код, фронтенд-исходники
и `[web]`-extra не удаляются — затрагиваются только `docker-compose.yml` и документация.

Принятые решения (brainstorming):
- **Скоуп:** только из compose (вариант A), фичу на хосте сохраняем.
- **Метод:** полностью вырезать блок `services.web` (не прятать за compose-profile).

## Изменения

### 1. `docker-compose.yml`

Удалить весь блок `services.web`:
- `build: { context: ., dockerfile: web/Dockerfile }`
- `environment.PG_DSN`
- `ports: ["127.0.0.1:8000:8000"]`
- `depends_on: ["paradedb"]`
- сопроводительный комментарий блока

После правки:
- `services`: `paradedb` + `neo4j`.
- `volumes`: `paradedb_data` + `neo4j_data` — **без изменений** (у `web` своего тома нет).

Результат: `docker compose up -d` на свежем клоне поднимает только инфраструктуру, без
node+python сборки фронта → ошибка устранена.

### 2. Документация (синхронизация — убрать обещания «compose поднимает web»)

**`CLAUDE.md`:**

- `:51` — удалить строку «Проще: `docker compose up -d` поднимает админку как сервис web (:8000) — фронт собирается в образе.»
- `:110` — в инварианте наблюдаемости убрать «или сервис `web` в docker-compose»; оставить
  «Веб-админка (FastAPI `reviewer serve`) читает ту же БД».
- `:52` — строка хостового запуска (`pip install -e ".[web]" … reviewer serve`) **остаётся**
  без изменений (валидна).

**`README.md`:**

- `:175` — из комментария `docker compose up -d` убрать «+ web admin (:8000)».

> а не по номеру (правки выше могут сдвигать последующие строки в том же файле).

### 3. Что НЕ трогаем

Фича остаётся доступной на хосте, поэтому сохраняем без изменений:
- `reviewer/web/` (api.py, app.py, history.py, schema.sql),
- `web/Dockerfile` — становится «осиротевшим» от compose, но оставляем: позволяет при
  желании собрать админку вручную (`docker build -f web/Dockerfile .`),
- `web/frontend/` (исходники SPA),
- `[web]`-extra в `pyproject.toml`,
- команду `reviewer serve` и её код,
- запись истории прогонов (`review_runs` / `review_findings`, `REVIEW_HISTORY`).

## Проверка

Python-код не затрагивается → новых юнит-тестов не требуется. Достаточно:

1. `docker compose config` — парсится без ошибок и в выводе **нет** сервиса `web`
   (например, `docker compose config --services` → только `paradedb`, `neo4j`).
2. Grep по докам не находит утверждений, что compose поднимает web:
   ```
   grep -rniE "сервис web|web admin \(:8000\)|docker-сервиса web|поднимает админку как сервис web" CLAUDE.md README.md .env.example
   ```
   → пусто.
3. Существующие тесты `.venv/bin/pytest -q` остаются зелёными (sanity — Python не менялся).

## Вне скоупа

- Удаление самой фичи наблюдаемости (вариант B) — явно отвергнуто.
- Перенос `web` за compose-profile — явно отвергнуто (выбрано полное удаление блока).
- Любой рефакторинг `reviewer/web/` или фронтенда.
