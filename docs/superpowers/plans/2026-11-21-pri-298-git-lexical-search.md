# PRI-298 Git Lexical Search Implementation Plan

> **For agentic workers:** Use superpowers:subagent-driven-development and TDD. Steps use checkbox syntax for tracking.

**Goal:** Добавить в solve-task опциональные проверяемые ссылки на файлы из Git и измерить их вклад.

**Architecture:** BM25 читает снимок Git и возвращает пронумерованные фрагменты существующего формата. Сборка секции `code` выделяет дополнительным фрагментам часть текущего бюджета. Replay переиспользует ранжирование и распределение слотов.

**Tech Stack:** Python, Git plumbing, pytest, замороженный replay и генератор брифов PRI-278.

**Spec:** `docs/superpowers/specs/2026-11-21-pri-298-git-lexical-search-design.md`

## Global Constraints

- Дефолт 0, верхний предел 3. Новые фрагменты входят в прежний бюджет файлов и символов.
- Содержимое читается с указанного SHA. Применяются игноры и ограничения источника.
- Итоговые ссылки считаются только по реально переданным строкам. Все три режима используют одинаковые лимиты.

## Review Focus

- Произвольный Git ref, изменения рабочего дерева и симлинк проверяются в реальном временном репозитории.
- Более трёх файлов и длинная строка проверяют квоту и ограничение фрагмента.
- Недоступный клон и пустая выдача проверяют сохранение гибридного контекста.
- Секция тестов изолирована от источника. Строка Git-фрагмента проходит имеющуюся проверку ссылок.
- Оба экспериментальных корпуса содержат пары для каждого режима. Оценщик разделяет попадания в контекст и принятые ссылки.
