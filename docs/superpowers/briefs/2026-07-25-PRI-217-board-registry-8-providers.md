## Constraints / open questions
- **База отстаёт.** base-индекс ветки `dev` в reviewer отстаёт примерно на 20 коммитов от рабочего дерева — цитаты `path:line` из `search_codebase` могли быть смещены; для всех критичных файлов (`registry.py`, `base.py`, `http.py`, `setup.py`, `contract.py`, `__init__.py`, `markup.py`, `errors.py`, `provider_credentials.py`, `jira.py`, `docs/board-providers.md`) номера строк сверены через прямой `Read`/`grep` локального рабочего дерева и актуальны на момент брифа.
- **criteria=[] в сторе.** Требования и критерии приёмки взяты из description задачи (сектор «Критерии приёмки»), не из поля `criteria`.
- **Кроссплатформенность / мульти-CLI (явное требование пользователя).** Решение — это плагин, используемый через разные AI-CLI (Claude Code, Codex, Cursor, Gemini, …) на разных ОС (macOS/Linux/Windows). Все новые provider-модули, `acquisition`-хуки в `setup.py` и любые правки `install.py`/`reviewer/entrypoints/cli.py` обязаны: (а) не полагаться на POSIX-специфичные пути/shell — использовать `pathlib.Path`, существующие кроссплатформенные хелперы `_home()`/`default_env_path()`/`platform.system()`; (б) не привязываться к конкретному AI-CLI-харнессу — вся server-side логика (registry/http/setup) уже CLI-агностична (чистый Python + httpx + Click), но `docs/board-providers.md`/README/skill-промпты не должны неявно предполагать, что setup идёт только из Claude Code; (в) `click.launch(url)` уже кроссплатформенный (использует `webbrowser`/платформенные `open`/`start`/`xdg-open` под капотом) — держаться этого паттерна для любых новых «открыть страницу токена» шагов, не звать `subprocess.run(["open", ...])` напрямую.
- **Общий транспорт — не готов, а частично реализован независимо.** `BoardHttpClient` (`http.py`) существует и уже используется отдельно (задача текста подразумевает, что jira/yougile/youtrack его НЕ используют — каждый пишет свой httpx wrapper). Шаг 7 задачи требует явно вынести повторяющуюся логику ДО 8 новых файлов; открытый вопрос — рефакторить ли существующие 3 адаптера на `BoardHttpClient` заодно (задача явно требует только «чтобы 8 новых файлов не копировали логику», не требует ретрофита старых 3) — решить на брейнсторме, т.к. затрагивает уже зелёные тесты `test_jira_*`/`test_yougile_*`/`test_youtrack_*`.
- **Разнородность API-моделей адаптеров.** GitHub Issues — REST + labels/milestone/Projects statuses (нет нативного workflow-статуса как Jira/YouTrack). Trello — REST v1 key+token (в URL query, не заголовок — иная модель кредов, чем Bearer/Basic у существующих 3). Linear — GraphQL (первый GraphQL-адаptер в кодовой базе; `BoardHttpClient.request_json` рассчитан на обычный REST-цикл method/path/status — нужно решить, обёртывать ли GraphQL поверх него или писать отдельный тонкий GraphQL-клиент). ClickUp/Asana/Kaiten/Weeek/Yandex Tracker — REST, но с разными полями пагинации/статусов; Asana — html_notes (markup.py уже подходит), Kaiten/Weeek — self-hosted base URL как non-secret `ProviderOptionSpec`, Yandex Tracker — YFM-разметка (не HTML — `markup.py` может не подойти без адаптации) и обязательные `X-Org-ID`/`X-Cloud-Org-ID` заголовки в credential-spec (нетривиальный multi-field credential с условной обязательностью — org vs cloud-org).
- **Тестирование 8 внешних API без сети — открытый вопрос для брейнсторма.** Contract-suite паттерн (httpx.MockTransport) масштабируется, но GraphQL (Linear) потребует иной формы мока (POST с телом query, не path-based роутинг) — решить единый подход к state-machine мока для GraphQL vs REST в `contract.py`.
- **Скоуп/фазирование.** Эпик оценивается как один крупный PR с 8+1(транспорт) коммитами; открытый вопрос на брейнсторм — резать ли на несколько последовательных PR (например, по 2-3 провайдера) для управляемости ревью, учитывая инвариант «partial registration запрещена» (значит промежуточные PR либо мержат только полностью зарегистрированные типы, либо это одна долгая ветка).
- **Версионирование/манифесты.** Любая правка `plugin/`-контента и/или бамп `pyproject.toml` требует прогона `update_codex_plugin_manifest.py` перед коммитом — иначе падают install-тесты в CI (гейтится только на `main`, но лучше держать манифесты синхронными на протяжении веток на `dev`).
