## Task — ключ ID-306 (алиас PRI-252), статус «Запуск / CI / хуки». Два прогона `reviewer index` на одном коммите dev дали разное число рёбер графа (33922 vs 32609) при одинаковых 7173 узлах; после второго прогона CALLS 32480 / IMPLEMENTS 129 против заявленных в спеке PRI-251 327 IMPLEMENTS. Код извлечения CALLS и merge-логика (dict.fromkeys) между замерами не менялись, индексируемый код тоже; повторные прогоны в текущих условиях детерминированы (32609 дважды). Обнаружено при живой приёмке PR #199 (PRI-251); на критерии PRI-251 не влияет. `criteria` в сторе пуст, но в описании есть явный раздел «Критерии приёмки»:
  1. Причина расхождения установлена и подтверждена воспроизведением (не гипотезой).
  2. Число рёбер по типам после индексации видно в выводе `reviewer index`.
  3. Значимая просадка полноты графа относительно предыдущего индекса той же ветки не проходит молча.
  4. Если причина в окружении worktree — зафиксировано в CLAUDE.md как неочевидный факт.

## Constraints / open questions — Гипотеза «worktree без активного venv/установленных зависимостей → pyright резолвит меньше типов → меньше type-aware рёбер» подкреплена кодом (докстринг `run_scip_python`, отсутствие шага подготовки окружения в `add_worktree`), но критерий 1 требует именно воспроизведения на одном коммите в обоих условиях, а не полагания на правдоподобие. Открытых PR/веток по PRI-252 нет (`get_task_context` вернул только PR #199, который относится к родительской PRI-251).
