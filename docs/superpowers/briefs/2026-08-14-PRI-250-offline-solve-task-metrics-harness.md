https://ru.yougile.com/team/686c049c8af8/#PRI-250

## Task
Ключ PRI-250 (ID-304), статус «Бэклог». Превратить одноразовый спайк-скрипт `eval/pri246_solve_task_cost.py` (PR #197, PRI-246) в переиспользуемое ядро офлайн-харнесса: парсер токен-блока, экстрактор путей брифа, ground truth по PR-мержам, классификатор путей, core-recall. Требования: (1) взвешенная цена вместо сырой суммы токенов (output ×5, cache-write ×1.25, cache-read ×0.1 — сырое завышает в 4.1×); (2) история срезов (JSONL) + режим сравнения с дельтами; (3) полная цена задачи «под ключ» с окном от вызова скилла до PR/завершения, независимым от числа правок брифа; (4) тест на инвариант ground truth (только «Merge pull request #N from…», не sync-мержи); (5) прогноз цены/core-recall с разбросом; (6) одна команда, задокументированная в README.md/README.ru.md; (7) остаётся офлайн-инструментом в `eval/`, юнит-тесты без внешних сервисов. Критерии приёмки — 8 пунктов, см. описание задачи (поле `criteria` в трекере пустое, но список приёмки полностью раскрыт текстом описания — пробела нет).

## Constraints / open questions
- Дублирование методологии с PRI-249 явно запрещено задачей-источником («общий расчёт метрик не должен быть написан дважды») — при проектировании ядра стоит сразу решить, куда/как переиспользовать код: чистый модуль в `eval/` без зависимостей на `reviewer/*`, либо общий модуль, из которого PRI-249 сможет импортировать (второе противоречит «харнесс не попадает в продакшн-путь reviewer», п.8 критериев — вероятно, ядро должно остаться в `eval/`, а PRI-249 при реализации явно скопирует/адаптирует, либо `eval/` станет непродакшн-зависимостью reviewer, что нужно явно решить в спеке).
- Окно полной цены «под ключ» (п.4 задачи) требует решить источник данных: новый хук в реальном времени vs ретроспективный разбор транскриптов `~/.claude/projects/` — задача явно оставляет это открытым вопросом («Решить, берётся ли число из нового хука или ретроспективно из транскриптов»), и как связать сессию с ключом задачи (сейчас связь идёт только через маркеры в user-сообщении, см. `find_window_start`).
- Взвешивание бакетов (output ×5, cache-write ×1.25, cache-read ×0.1) — числа из спайка PRI-246, зафиксированы как заданные в описании задачи; в `eval/pri246_solve_task_cost.py` в просмотренном диапазоне (50-361) явного кода взвешивания не встретилось в процитированных фрагментах — надо проверить, есть ли он уже в скрипте (строки не просмотрены целиком) или его нужно добавить с нуля.
- Пустой core-знаменатель (10/45 задач в спайке PRI-249) — должен учитываться отдельно как «нет точки измерения», не как нулевой recall; это уже частично видно в `categorize_miss`/`is_core_production_path`, но явного «no-measurement»-состояния в процитированном коде не подтверждено — проверить при рефакторинге.
- Задача в статусе «Бэклог», критерии приёмки (`criteria` в TaskBrief) пустые как структурированное поле — весь список приёмки жил только текстом в `description`; при `index_task`/дальнейшей работе стоит не терять этот список, раз структурного поля нет.
