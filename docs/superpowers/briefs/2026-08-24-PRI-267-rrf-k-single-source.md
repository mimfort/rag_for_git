## Task

- **PRI-267** (ключ стора `ID-321`, статус «Бэклог»); долг зафиксирован в `CLAUDE.md:422` последним предложением абзаца про мультизапрос секции `code` (PRI-255) и никогда не закрывался.
- Константа слияния RRF объявлена трижды и независимо; SQL не импортирует Python, поэтому питоновской копии не избежать — но ни один тест эти значения не связывает.
- Расхождение `k` между слиянием подзапросов и RRF внутри одного гибрида пройдёт молча: ранжирование поедет, ни один тест не покраснеет, обнаружится в лучшем случае просадкой метрики брифа, где причину искать уже негде.
- **Что сделать (из задачи):** (1) guard-тест, читающий числовой литерал из SQL-текста обоих store и сверяющий его с `RRF_K`; (2) рассмотреть альтернативу — подставлять значение в SQL параметром из единой константы, применимо только если не портит план запроса, проверить `EXPLAIN`; (3) выбрать один вариант и зафиксировать причину выбора в комментарии рядом с константой.
- **Критерии приёмки (из задачи):** (1) изменение `k` в одном из трёх мест без остальных красит тест; (2) ранжирование не меняется — существующие тесты ретрива зелёные, числа эвала не двигаются; (3) при выборе параметризации подтверждено, что план запроса не деградировал.
- Автор помечает задачу как мелкую, изолированную, разминочную: замер на корпусе не требуется.
