## Task
- **PRI-162** (S, «Плагин/агент (скилы)»). `search_codebase` по умолчанию `include_tests=False`, поэтому бриф solve-task не показывает, **как** тестируются похожие фичи — а бриф уходит в `brainstorming → writing-plans → subagent-driven-development/TDD`, где имплементер стартует с теста без образца «как у нас принято».
- **Сделать:** (1) в шаг 3 добавить опциональный точечный тест-ретрив — один `search_codebase("<как тестируется область задачи>", include_tests=True)` для нескольких ближайших символов; (2) в скелет брифа (шаг 4) добавить секцию «Тесты для образца — ≤2–3 файла/символа: `path:line` — что мокается / какой паттерн»; (3) guard-тест.
- **Не раздувать:** тот же rank-based relevance-фильтр и `(dropped N: …)`, что и для кода. **Fail-open:** тестов нет → секцию опустить; обычный код-ретрив (без тестов) не меняется.
- **Приёмка:** на задаче с протестированными аналогами бриф несёт ≤3 тест-образца с `path:line`; обычный ретрив не меняется; downstream TDD получает конкретный паттерн для mimic.
