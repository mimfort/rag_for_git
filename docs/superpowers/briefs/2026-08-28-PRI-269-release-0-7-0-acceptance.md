## Constraints / open questions
- Нормализованный `task.criteria` пуст (`[]`) — все 13 шагов и 11 критериев приёмки существуют только текстом внутри `description`, машиночитаемого списка нет.
- Наблюдение сессии №1 (проверено): шаг 8/критерий 6 — стартовая панель solve-task показана ровно одна, три вопроса, дословные заголовки `Brief model tier`, `Interaction mode`, `Execution strategy`, без переформулировок; выбраны `mid`/`auto`/`auto`.
- Наблюдение сессии №2 (частично проверено): шаг 2/критерий 4 — при живых ParadeDB и Neo4j `prepare_task_context` на реальной задаче PRI дал `gaps: []` и полный payload из девяти ключей; этот бриф — прямое следствие того прогона.
- Наблюдение сессии №3 (потенциальный пробел, родственный критерию 8): при недоступном Voyage (403 от датацентрового IP, HTML вместо JSON, воспроизводится и без ключа) при ЖИВЫХ хранилищах `prepare_task_context` вернул `gaps` с `cause: "unknown"`/`remedy: null` для секций `task`/`subsystems`, секции `code`/`test_exemplars` — «(ничего не найдено)», `related.similar` — «(task search unavailable)», `sync_board` дал `failed: 3` с `embedder: APIError: HTTP code 403`. Формально классификация верна (Voyage — не хранилище, `reviewer start` его не чинит), но пользователь получает обезличенный `unknown` без указания на настоящую причину — критерий 8 требует отличимости причины, а этот случай не входит ни в один из 13 шагов. Открытый вопрос: нужен ли отдельный `cause` (например, `embedder_unavailable`) или отдельная задача PRI со ссылкой на этот замер.
- Related work: `related.linked` в payload содержит только саму задачу, а не PRI-268/267/265 из `task.links`; PRI-265 не нашёлся ни там, ни в top-8 `similar` (выдача усечена, «8 из 30»). Контент PRI-268/267 восстановлен через `similar`; PRI-265 в брифе не подтверждён отдельным источником, но его требования и так полностью в `description` этой задачи.
- Задача по природе приёмочная: «реализация» — это прогон 13 шагов с фиксацией замеров по 11 критериям, а не написание кода. Часть шагов (3, 6, 7, 11, 12, 13) требует останавливать инфраструктуру, портить креды в каноническом `.env` и создавать конкуренцию за пул соединений — такие действия должен явно санкционировать человек до выполнения, не Claude в одиночку.
- Известное ограничение самой задачи (из текста): unit-тесты доказывают поведение только на фейках; пункты про время ответа, расход Voyage и живое поведение скилла проверяются исключительно вручную на реальной установке — эвал/замеры не автоматизируются этим брифом.
