# PRI-316 Границы источника similar-diffs

Сравнение выполнено на одном локальном снимке `42f3522dda497c51e1606e27c9434ae3847d859d` ветки dev. В обоих вариантах учитывалось до 200 совпавших коммитов на ключ без учёта регистра. Пути merge-коммитов получены из диффа по первому родителю. Для контроля взяты два ключа с точными совпадениями.

| Ключ | Коммитов до | Коммитов после | Путей до | Путей после |
| --- | ---: | ---: | ---: | ---: |
| PRI-27 | 29 | 0 | 112 | 0 |
| PRI-29 | 41 | 0 | 180 | 0 |
| PRI-25 | 48 | 0 | 147 | 0 |
| PRI-307 | 3 | 3 | 12 | 12 |
| PRI-312 | 2 | 2 | 2 | 2 |

У положительных контролей совпали состав и порядок путей. Прежний фолбэк для трёх коротких ключей возвращал пути коммитов с другими ключами. Этот замер характеризует один источник кандидатов.

В отдельном Git-тесте точный алиас из имени ветки в сообщении merge-коммита сохранил свой путь. Коммит с более длинным ключом и коммит после снимка исключены. При недоступном снимке сборщик возвращает диагностический пробел. Тест с записями двух репозиториев проверяет передачу фильтра `repo` фактическому запросу истории прогонов.

## Воспроизведение

```bash
python -m pytest -q -m integration tests/services/test_gitutil_grep.py
python -m pytest -q tests/retrieval/test_augment.py
sha=42f3522dda497c51e1606e27c9434ae3847d859d
key=PRI-27
git log "$sha" -n200 -i --format=%H --grep="$key"
git log "$sha" -n200 -i -E --format=%H --grep="(^|[^[:alnum:]])$key([^[:alnum:]]|$)"
git log "$sha" -n200 -i --name-only --diff-merges=first-parent \
  --pretty=format: --grep="$key" | awk 'NF && !seen[$0]++' | wc -l
python -c 'from reviewer.gitutil import paths_touched_by_grep as paths; import sys; print(len(paths(".", sys.argv[2], limit=200, indexed_sha=sys.argv[1])))' "$sha" "$key"
```
