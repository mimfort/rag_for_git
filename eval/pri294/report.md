# PRI-294. Критерии приёмки в подзапросах solve-task

Парный прогон от 21.11.2026 восстановил 31 из 31 пропущенного критерия. Число подзапросов осталось прежним для всех десяти задач. На заранее размеченных фрагментах покрытие подтверждений в секции кода и брифе осталось прежним.

## Состав прогона

- Семь затронутых карточек содержат 83 критерия. Три контрольные карточки содержат 18 критериев. Исходные версии взяты из reviewer store, сохранены перед прогоном и одинаковы для обоих вариантов.
- Исходный разбор взят из `bfcefdf96b9ea67beea766aa75adf0acbbcbcdc2`. Кандидат для замеров — `e2f1150a9edc6fbe0b6a9052972eb98343b03671`. Проверка `646518fb403f0c0b7705d09129927400b9ff5b53` дала те же массивы запросов и исключений для всех десяти карточек.
- Оба варианта использовали живой `dev@bfcefdf96b9ea67beea766aa75adf0acbbcbcdc2`, `voyage-code-3`, тот же производственный гибридный поиск и граф. На секцию кода — 20 файлов, по одному фрагменту на файл, по 975 символов исходника на фрагмент. До трёх файлов может добавить `similar-diffs`. Его вход зафиксирован через Git-фолбэк по тем же похожим карточкам. История ревью отключена для прогона, чтобы обходиться без её ленивой миграции.
- Для сравнения подтверждений независимо размечены два критерия на карточку. Каждому соответствует конкретная строка исходного кода, теста или документации. Из 20 меток 14 доступны секции `code`. Остальные шесть лежат вне её выдачи, включая один тестовый путь. Это проверка присутствия свидетельства реализации по выбранному критерию. Она не проверяет весь критерий и не экстраполируется на оставшиеся критерии.
- Критерий считается представленным в запросе при наличии всего текста пункта после нормализации пробелов и регистра. Секция кода получает зачёт за полностью видимую строку с заданным якорем. Бриф получает зачёт за ссылку на полностью видимую строку того же фрагмента. Совпадения с точной строкой якоря считаются отдельно.

Брифы получены одним выборочным ответом модели на карточку в каждом варианте. Разметка и объём прогона позволяют описать наблюдение, но не отделить влияние состава выдачи от вариативности модели.

Для каждой карточки парсер измерялся пятью сериями по 100 вызовов, поиск — двумя повторами. Порядок вариантов чередовался. В таблице медианы по карточкам от медиан повторов. Общий предварительный расчёт 213 уникальных эмбеддингов занял 24,44 с. Это время исключено из замеров поиска. Для брифов использованы четыре пакета из 3, 3, 3 и 1 карточки в каждом варианте, одинаковый промпт и `gpt-6-luna` в режиме `low`. Время включает запуск Codex CLI. Показатели задержки описывают этот прогон, в том числе шум внешних сервисов, и не оценивают скорость холодного `prepare_task_context`.

## Воспроизведение

Запустить из корня репозитория с настроенным reviewer и указанной версией индекса. Каталог `/tmp/pri294-replay` хранит снимок карточек, точные массивы запросов, отрисованные фрагменты и сырые ответы модели.

```bash
python -m eval.pri294.replay --work /tmp/pri294-replay
python -m eval.pri294.briefs --work /tmp/pri294-replay
python -m eval.pri294.score --work /tmp/pri294-replay --output /tmp/pri294-results.json
```

В [results.json](results.json) записаны хеши точных запросов в порядке передачи, номера представленных и исключённых критериев, покрытие якорей и наблюдения задержки по карточкам. [evidence.json](evidence.json) содержит разметку. Хеши модельного ввода сверяются с парными секциями `code`. Предварительный отдельный baseline отличался от парного в трёх секциях. Для итоговой оценки исходные брифы собраны повторно на парном выводе.
