# PRI-317. Покрытие явно указанных путей в solve-task

## Методика

25.11.2026 сравнили штатную сборку и вариант с учётом точных относительных путей. Обе стороны вызывали `MCPReviewService.prepare_task_context` с одними и теми же входами без прогрева доски. Индекс ветки `dev` для `mimfort/rag_for_git` оставался на Git-снимке `42f3522dda497c51e1606e27c9434ae3847d859d`. Считали явно названные Python-пути, для которых прямой запрос к индексу той же ветки вернул чанк. Путь засчитывали, если соответствующая секция содержала хотя бы одну полностью видимую строку фрагмента.

Вариант выделяет до двух мест на секцию для явно названных файлов. Добавленные файлы расходуют общую квоту подмешивания и входят в общий лимит в 20 файлов. Пути обрабатываются отдельно для кода и тестов с учётом `paths.ignore`. URL, имена без пути и упоминания в справочных разделах карточки исключены из точного поиска.

Подбор включает случаи с пропусками и контрольные случаи. При заполненных секциях добавление точного пути меняет состав выдачи. Разметка учитывает только явно упомянутые пути, поэтому замер оценивает их присутствие. Полноту остальных релевантных файлов и качество итогового брифа в этом прогоне не измеряли.
