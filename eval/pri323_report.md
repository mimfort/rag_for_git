# PRI-323. Точный ключ задачи при поиске PR-мержей

Проверка от 25.11.2026 на истории rag_for_git, доступной из коммита `09c0a4ce9c36b12a8986b76968bd84b83b0b9a18`. Старый `git log --grep` находил ключ по подстроке. Например, запрос `PRI-27` находил сообщения с ключами `PRI-270` и `PRI-275`. После фильтрации по форме сообщения такие коммиты пополняли список PR и добавляли их файлы в знаменатель метрики исходной задачи.

Поиск использует те же границы ключа и экранирование, что и поиск файлов по Git-истории в solve-task. Регистр по-прежнему не учитывается. Ключ можно найти в имени ветки в заголовке или в теле merge-коммита. При штатном пересчёте рассматриваются все локальные ссылки Git.

| Ключ | PR-мержи до правки | PR-мержи после правки |
|---|---|---|
| PRI-27 | 6: #247, #235, #233, #232, #231, #229 | 0 |
| PRI-29 | 9: #258, #257, #256, #255, #254, #251, #252, #250, #248 | 0 |
| PRI-25 | 9: #214, #213, #212, #211, #210, #209, #200, #199, #198 | 0 |
| PRI-313 | 1: #272 | 1: #272 |
| PRI-318 | 1: #277 | 1: #277 |

В трёх проверенных случаях из выборки исключились 24 ложные пары «задача и PR». Обе контрольные пары сохранились. Это проверка отбора PR, для неё не требовались эмбеддинги, модель и запись в БД.

## Воспроизведение

Из корня репозитория с указанным Git-объектом запустите следующий код. В обоих вариантах он выбирает одну и ту же историю и применяет штатный фильтр merge-коммитов.

```python
from pathlib import Path

from reviewer.metrics.brief_quality import ground_truth as gt

sha = "09c0a4ce9c36b12a8986b76968bd84b83b0b9a18"
run_git = gt.git_runner(Path.cwd())


def pinned(args):
    return run_git([sha if arg == "--all" else arg for arg in args])


for key in ("PRI-27", "PRI-29", "PRI-25", "PRI-313", "PRI-318"):
    def legacy(args):
        return pinned([*args[:-2], f"--grep={key}"])

    old, _ = gt.filter_pr_merges(gt.merge_rows(key, legacy))
    new, _ = gt.filter_pr_merges(gt.merge_rows(key, pinned))
    print(key, [pr.number for pr in old], [pr.number for pr in new])
```
