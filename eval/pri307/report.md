# PRI-307 Проверка ссылок сохранённого брифа

Проверка читает метаданные брифа и локальные объекты Git. При сохранении подтверждённых ссылок записываются репозиторий, ветка, исходный SHA, идентификаторы файловых блобов и хеш списка координат. При повторном открытии команда сравнивает их с `HEAD`. Совпавший блоб пропускается без чтения его текста. Для изменённого блоба сдвиг предлагается только при единственном точном совпадении непустой строки в обоих снимках. Ссылки на файлы с локальными правками требуют проверки рабочего дерева.

## Парный прогон

Из 30 базовых брифов PRI-278 взяты ссылки на полностью показанные строки. Исходный текст проверен по `base_sha` карточки. Исключены 54 ссылки с несовпавшим текстом, 16 с номерами за пределами показанных строк и 19 с путями вне контекста. Для проверки в пределах недели выбран ближайший следующий базовый снимок из того же архива по времени коммита. Он должен содержать исходный снимок в истории. Для 10 из 105 пригодных ссылок в архиве не оказалось такого снимка. Для второй проверки взят зафиксированный `solution_sha` каждой задачи.

| Снимок для сверки | Задач | Ссылок | Прежний номер указывает на тот же текст | Сдвиг найден | Несколько совпадений | Текст изменился |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| Следующий снимок архива в пределах недели | 26 | 95 | 66 | 24 | 3 | 2 |
| Коммит реализации задачи | 29 | 105 | 73 | 27 | 3 | 2 |

На ближайшем снимке алгоритм обнаружил все 29 изменений. На коммите реализации обнаружены все 32 изменения. Для обоих сравнений сверка с `git show` не выявила ложных предупреждений. Все 24 и 27 предложенных номеров указывали на единственное точное совпадение в целевом файле. Выборка измеряет совпадение текста и координат в одном репозитории. Смысловая эквивалентность отрывков и случаи новых имён файлов в архивном прогоне не измерялись. Сценарии удаления файла, изменения рабочей копии и отсутствия исходного снимка проверены на отдельном тестовом Git-репозитории.

Медиана времени сверки составила 144,4 мс на 26 задачах в первом сравнении и 145,1 мс на 29 задачах во втором. Измерялся локальный вызов сравнения ссылок с Git без прогретых кэшей объектов в Python. В измерение не входят чтение брифа, разбор Markdown, проверка рабочей копии и построение плана. Языковая модель, эмбеддинги и индекс в прогоне не используются.

## Воспроизведение

Из полного клона rag_for_git:

```bash
python -m eval.pri307.replay --output /tmp/pri307-replay.json
```

JSON содержит точные исходные и целевые SHA по каждой карточке, отдельные вердикты для ссылок, причины исключения и время по задачам. Исходные данные входят в [архив PRI-278](../pri278/).

После сохранения новый бриф можно проверить отдельно:

```bash
reviewer brief-provenance path/to/brief.md --path /path/to/clone
```

Команда не редактирует бриф. Для старого файла без метаданных возвращается `legacy_brief`.
