# PRI-310. Порядок фрагментов в брифе solve-task

## Методика

Сравнение проведено 25.11.2026 на 20 задачах из корпуса PRI-278, в том числе на пяти задачах с ядром от десяти файлов. Эти задачи не входили в исходный пилот чередования по краям на десяти независимых карточках. Все задачи относятся к rag_for_git. Постановки, разметка и Git-снимки взяты из [корпуса](../pri278/corpus.json). Секции кода взяты из режима `all-pool-30` гибридного поиска в [замороженном архиве](../pri278/pool_size/evidence.jsonl.gz).

Во всех условиях сохранены байтовый объём секции, состав и текст блоков, лимит в 20 файлов и карта полностью видимых строк. Сравнили три способа расстановки фрагментов:

- `rank` сохраняет порядок архива.
- `edges` ставит нечётные исходные ранги по возрастанию, затем чётные ранги по убыванию. Так первые позиции исходной выдачи расходятся к двум краям.
- `graph_fixed` оставляет на исходных местах пути, добавленные расширением по графу, и применяет ту же перестановку к остальным местам. Признак добавления по графу берётся из ранжированного и расширенного списков путей. Экспертная разметка участвует только в оценке.

Каждое условие дважды прошло четыре одинаковых по составу пакета по пять задач. Условия внутри пакета запускались последовательно. В первом повторе последовательность циклически сдвигалась между пакетами, во втором обращалась для каждого пакета. Пакеты запускались параллельно. Использована модель gpt-6-luna с уровнем рассуждения low через Codex CLI в эфемерных запусках с одинаковыми промптом и JSON-схемой. В запросы передавались только ключ, постановка и секция кода. Вызовы инструментов проверялись по журналу событий.

Файл засчитывается, если в брифе есть хотя бы одна ссылка на его полностью видимую строку в соответствующей секции. Покрытие считается по всем размеченным путям в срезе. Позиционный срез разбивает блоки на три группы по номеру в данной выдаче. В нём доля считается только среди видимых размеченных путей. Входные и выходные токены берутся из журнала Codex. Длительность измеряется для пакета из пяти задач и включает клиентский запуск.

Заранее установленный порог для рекомендации составляет не менее +5 п.п. покрытия ядра по сумме повторов при сохранении покрытия зависимостей на всех задачах и отдельно на крупных. Пропущенные или повторные брифы блокируют рекомендацию.

При проверке ссылок отклонены 63 ссылки в режиме `rank`, 70 в `edges` и 79 в `graph_fixed`. Покрытие рассчитано по подтверждённым ссылкам.

## Решение

Покрытие ядра снизилось на 1,01 п.п. в обоих вариантах. При расстановке по краям общее покрытие зависимостей выросло на 1,09 п.п., при фиксации графовых путей снизилось на 1,09 п.п. На крупных задачах по всем трём условиям подтверждены 6 из 22 зависимостей.

Оба варианта остались экспериментальными. Вывод относится к одному репозиторию, одному набору снимков и двум повторам одной модели.

## Воспроизведение

[Архив ответов](responses.json.gz) содержит SHA Git-снимков, контрольные суммы входов по пакетам, промпта и JSON-схемы, название модели, версию клиента, ответы и статистику вызовов. [Таблица метрик](metrics.json) хранит оценки по повторам, задачам и позиционным группам.

```bash
# Проверка сохранённых ответов
.venv/bin/python -m eval.pri310.replay score --work eval/pri310

# Новый запуск и подсчёт метрик
.venv/bin/python -m eval.pri310.replay run --work /tmp/pri310-replay
.venv/bin/python -m eval.pri310.replay score --work /tmp/pri310-replay
```
