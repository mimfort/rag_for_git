# PRI-319. Атомарная публикация базового индекса PostgreSQL

## Воспроизведение

Проверка выполнена 25.11.2026 на изолированной ParadeDB. В снимке A есть два файла, `a.py` и `b.py`. Снимок B изменяет `a.py` и удаляет `b.py`. После записи новых чанков имитируется сбой операции удаления. Для чтения используется отдельное подключение.

На `09c0a4c` во время обновления и после его сбоя BM25 возвращал чанк B из `a.py` и чанк A из `b.py`. В обоих случаях метаиндекс указывал на A. В дополнительной проверке MCP на Git-снимке A расходилась одна из четырёх показанных строк. Удалённый в B файл `b.py` подтверждался по A, ссылка на изменившуюся строку `a.py` отклонялась.

| Момент чтения | Чанки до исправления | SHA до исправления | Чанки после исправления | SHA после исправления |
| --- | --- | --- | --- | --- |
| До обновления | оба из A | A | оба из A | A |
| После записи чанков, до удаления | один из A и один из B | A | оба из A | A |
| После имитации ошибки удаления | один из A и один из B | A | оба из A | A |
| После успешного повтора | один из B | B | один из B | B |

Чанки, удалённые пути и символы и новая метка публикуются в одной транзакции PostgreSQL. Эмбеддинги вычисляются перед её началом. Перед публикацией выполняется сравнение с меткой `(SHA, updated_at)`, прочитанной до подготовки. Блокировка по репозиторию и ветке защищает проверку и запись, в том числе при первом обновлении без прежней метки. Дополнительный тест задерживает первого издателя на вычислении эмбеддингов. Второй издатель успевает завершить публикацию, а устаревшая запись первого отклоняется. Полная индексация пустого дерева Python также обновляет только указанную ветку.

Граф Neo4j обновляется отдельной операцией. Эти эксперименты относятся к публикации PostgreSQL. Отдельные запросы длинной сборки контекста всё ещё могут выполняться по разные стороны успешной публикации.
