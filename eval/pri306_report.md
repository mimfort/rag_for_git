# PRI-306. Восстановление пропущенных брифов в пакетном replay

Проверка от 25 ноября 2026 г. на базе `09c0a4ce9c36b12a8986b76968bd84b83b0b9a18`. В первом Markdown-прогоне PRI-299 модель вернула пять из шести брифов и пропустила PRI-221. Прежний `check_briefs` прерывал запись всего пакета, поэтому через `run_batch` на диск попадало 0/6 брифов. Сырые события запусков остаются отдельными файлами.

## Поведение после изменения

Первый ответ фиксируется по ключам. Для каждого ключа сохраняется исходный текст брифа, если он непустой и встретился один раз. Ссылки проверяются по видимым строкам переданного фрагмента. Отсутствующий ключ, повторы, пустой или некорректный бриф и бриф без подтверждённых ссылок описываются разными статусами. Лишние ключи и записи без ключа учитываются отдельно.

Повтор получает только постановку и исходный контекст одной отсутствующей задачи. Перед обращением к модели попытка записывается в контрольную точку. После прерывания повтор учитывается как прерванный, а сохранённый первый ответ используется для продолжения. Попытка, завершившаяся ошибкой, сохраняет статус ошибки. Время и токены суммируются по завершённым ответам. Отдельный счётчик показывает число попыток без доступного учёта токенов.

SHA-256 связывает результат и контрольную точку с порядком задач, постановками, контекстом, промптом, JSON-схемой, версией проверки ссылок и настройками модели. Несовпадение или отсутствие отпечатка в старом файле требует отдельного каталога для нового прогона. Пакет сохраняется атомарно в прежнем `batch-*.json` с массивом `briefs`. Служебные файлы находятся в `.batch-ledgers/`. Сводки со строго парным сравнением по-прежнему требуют полных пар.

## Контрольное воспроизведение архива

Вход и первый ответ взяты из [PRI-299](pri299/report.md). Архивный вход проверяется по SHA-256 `4a9773cef65ef00d0bda3b1404337f5d035b7e1687a76d2c3dd32bcf087b8157`. Первый ответ получен в Codex CLI 0.170.0 на `gpt-6-luna` с усилием `low`. В проверке вместо ответа на одиночный запрос подставлен только бриф PRI-221 из полного второго Markdown-прогона. Проверка выполняется без обращения к модели и показывает работу восстановления на фиксированных ответах. Разметка [независимого корпуса PRI-278](pri278/independent-corpus.json) используется только для подсчёта метрик.

При подсчёте покрытие отсутствующего ответа равно нулю. Число размеченных файлов и набор задач одинаковы до и после подстановки. Все пять текстов первого ответа совпали посимвольно. В архивном первом обращении учтены 51 534 входных токена, в том числе 8 064 кэшированных, и 1 508 выходных. Стоимость отдельного обращения за PRI-221 неизвестна. Тест с заданными счётчиками проверяет сумму 100 + 20 входных и 2 + 2 выходных токена. Вероятность получить содержательный ответ при живом одиночном повторе здесь не измерялась.
