# Проверка ссылок в брифах крупных задач

Прогон от 25.11.2026 выполнен на коде `740f9e871e14010a05800153f7f930e0e34d2f60`. Проверены три способа сохранить полезный файл после выбора ссылки. Для крупных задач использован порог в десять файлов ядра. По разметке отобрали крупные задачи и посчитали покрытие. В запросы модели попадали постановки, отрывки или запись уже выбранной ссылки с её исходным пояснением.

## Исходные отказы

Проверены 142 ответа из архивов PRI-310 и PRI-299. Штатная сверка полностью видимых строк с Git не нашла расхождений и недоступных объектов в 40 410 проверках строк с учётом повторов.

В двух контрольных повторах PRI-310 на пяти крупных задачах брифы покрыли 34 из 168 файлов ядра. Из 23 отклонённых ссылок шесть указывали на ещё не засчитанный файл ядра, который уже был в секции кода. Это верхняя граница возможного прироста при исправлении координат в тех же фрагментах. В структурированных брифах PRI-299 таких возможностей было четыре по ядру и одна по зависимостям. Правило совпадения с единственным видимым объявлением символа, заключённого автором брифа в обратные кавычки, не нашло замен в обоих архивах.

## Повторная проверка отдельной ссылки

Два повтора на уже полученных брифах проверены через Codex CLI 0.170.0, модель `gpt-6-luna` с уровнем `low`. Модель получала прежнее пояснение и строки одного уже показанного пути. Она могла указать номер и точный текст строки, подтверждающей смысл пояснения, либо отказаться. Источником служили отдельно исходный видимый отрывок и новый отрывок длиной до 975 символов вокруг ошибочно указанной строки в том же Git-снимке. При переносе ссылки строка должна совпасть и с переданным отрывком, и с Git. Другие ссылки исходного брифа сохраняются. Вариант нового отрывка требует дополнительного показа исходного кода.

| Отрывок | Первый прогон, PRI-310, крупные | Второй прогон, PRI-310, крупные | Первый прогон, PRI-299, крупные | Второй прогон, PRI-299, крупные |
| --- | ---: | ---: | ---: | ---: |
| Исходное покрытие | 34/168 | 34/168 | 19/72 | 19/72 |
| Исходный отрывок, совпадение с разметкой | 34/168 | 35/168 | 21/72 | 21/72 |
| Новый Git-отрывок, совпадение с разметкой | 35/168 | 37/168 | 19/72 | 20/72 |

Каждый повтор охватывает два сохранённых ответа на каждую карточку. В PRI-299 знаменатель также включает один отсутствующий бриф. Оба совпадения из исходного отрывка на PRI-202 относятся к одной строке вызова поиска с передачей `top_k`. В исходном отрывке PRI-257 модель в одном повторе предложила строку графовой выборки для пояснения о гибридном поиске. Это формально проверяемая строка из нужного файла, которая не подтверждает пояснение. После смысловой проверки покрытие в обоих повторах PRI-310 с исходным отрывком осталось 34/168. В новых отрывках механизмы подтверждались на PRI-215, PRI-257 и PRI-170. На обычных задачах встречались предложения из путей вне разметки. В одном случае исходный отрывок подтверждал составление одиночного запроса, хотя пояснение описывало набор подзапросов.

Четыре вызова с исходным отрывком использовали 96 650 входных и 710 выходных токенов. Четыре вызова с новым отрывком использовали 97 990 входных и 710 выходных токенов. В замеры вошёл запуск клиента. Результат зависит от повтора, типа отрывка и состава карточек.

## Короткие идентификаторы строк

Для восьми крупных и пяти обычных задач проведено по два свежих парных прогона. Разметка, Git-снимки, количество файлов, длина UTF-8 секций, полный исходный текст, заголовки фрагментов и порядок файлов совпадали. В варианте с идентификаторами перед каждой строкой вместо исходного номера печатался уникальный для секции `@NNN` с сохранением ширины поля. Ответ ссылался на идентификатор. Перед проверкой вывод однозначно разворачивался в путь и номер строки. Штатный `verify_references` и потребитель Markdown подтвердили круговое преобразование 403 ссылок. Все 16 обращений завершились. Во входах использованы три крупные независимые карточки из предварительного корпуса и отдельные пять крупных карточек PRI-310.

| Корпус | Ядро крупных, исходный формат | Ядро крупных, идентификаторы | Ядро обычных, исходный формат | Ядро обычных, идентификаторы |
| --- | ---: | ---: | ---: | ---: |
| PRI-310 | 42/168 | 40/168 | 10/18 | 8/18 |
| PRI-299 | 32/72 | 22/72 | 24/36 | 20/36 |
| Сумма | 74/240 | 62/240 | 34/54 | 28/54 |

Суммарное покрытие зависимостей крупных задач снизилось с 12 до 9 попаданий при прежних 36 размеченных путях. В основном корпусе число подтверждённых путей вне разметки крупных задач увеличилось с 10 до 23. Число отклонённых ссылок снизилось с 28 до нуля. В варианте с идентификаторами отсутствовали два из 26 ожидаемых брифов. На одной крупной карточке модель вернула 59 ссылок, в том числе повторные ссылки на одни и те же пути. Входные токены снизились с 306 189 до 298 621, выходные с 8066 до 6775.

## Решение

Короткий идентификатор улучшил синтаксическую проверяемость, а покрытие ядра в обоих корпусах снизилось. Повтор по ошибочной ссылке дал отдельные подтверждённые попадания, но эффект различался между условиями, а дополнительный вызов дал и смысловые ошибки. На этой выборке оснований включать эти варианты в обычный solve-task нет.

## Воспроизведение

Из корня полного клона с установленными зависимостями. Сохранённые ответы читаются локально. Для сверки отрывков в Git нужны снимки, перечисленные в протоколе архива.

```sh
python -m eval.pri324.citations.replay score --output /tmp/pri324-citations.json
python -m eval.pri324.citations.repair --output /tmp/pri324-repairs.json
```

[Ответы и контрольные суммы входов](responses.json.gz) и [подсчёт по каждому брифу](results.json) относятся к парному прогону с короткими идентификаторами. [Повторные проверки ссылок](repairs.json.gz) содержат два набора отрывков с номерами исходных повторов, запросы и ответы модели. Оценка совпадения строки с Git воспроизводится автоматически. Примеры смысловых расхождений проверены вручную.

Для нового парного прогона коротких идентификаторов запустите `python -m eval.pri324.citations.replay run --work /путь/к/новому/каталогу`. Повторный прогон использует ту же постановку и модель из протокола.
