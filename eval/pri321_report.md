# PRI-321 Качество брифа в снимке PR

Сравнение выполнено 25.11.2026 на клоне rag_for_git с исходной версией `09c0a4c`. Для каждой пары сохранили один и тот же дифф до первого родителя merge-коммита и правила ядра из `.review.yml`. Сравнили содержимое найденного брифа в рабочей копии и в дереве merge-коммита. Различия в тексте нашли в двух из 85 пар, доступных по именам брифов. В обеих парах это один и тот же путь брифа PRI-223.

| PR | SHA merge-коммита | Ядро по текущему файлу | Ядро по снимку |
| --- | --- | ---: | ---: |
| #159 | `4978334e15df98ed739bee4daa5b3d6544002952` | 1/6 (16,7 %) | 3/6 (50,0 %) |
| #160 | `3fa8c15b629463cdcef12de72e183c64d8af3ad1` | 2/5 (40,0 %) | 3/5 (60,0 %) |

В контрольном репозитории незакоммиченный более новый бриф для того же ключа менял core-recall с 1,0 до 0,0 при прежнем SHA PR и диффе. При чтении снимка результат остался 1,0. В пересчёте корпуса копии брифа и повтор одного номера PR теперь дают одну строку измерения на ключ задачи и номер PR. При проверке всех 89 файлов брифов текущего корпуса получено 84 строки с разными парами «задача и PR». Запись подменили накоплением в памяти. Список ключей определяется файлами в дереве текущего HEAD. Незакоммиченные добавления и удаления не меняют состав корпуса. Сценарий охватывает ключи файлов, сохранившихся в этом дереве.

Если дерево Git доступно и подходящего файла в нём нет, метрика возвращает `no_brief`. Если нужный коммит отсутствует локально, результатом будет `brief_revision_unavailable`. Метрика не вычисляет числовые показатели в обоих случаях. Рабочая копия остаётся источником только при сознательном вызове без SHA.

## Воспроизведение

Регрессии запускаются без записи в базу и сетевых запросов.

```bash
python -m pytest -q tests/services/test_brief_quality.py tests/entrypoints/test_measure_briefs.py
```

Для исторического сравнения вызовите `reviewer.services.brief_quality.measure` по указанным SHA и без SHA. Передавайте один и тот же набор путей и статусов из `reviewer.metrics.brief_quality.ground_truth.changed_status`. Сценарий использует сохранённые Git-объекты одного проекта.
