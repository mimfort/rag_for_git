# PRI-320. Явные координаты в контексте задачи

Сравнили штатный поиск на коммите `09c0a4c` и отбор с учётом явной строки. Обе стороны читали один индекс ветки `dev` репозитория `mimfort/rag_for_git` на SHA `09c0a4ce9c36b12a8986b76968bd84b83b0b9a18`. Индекс и доска задач во время замера не менялись. Для каждого запроса в `prepare_task_context` передали текст ``Разбери поведение кода в `path.py:line`.``, `warm_board=False` и `include_brief_evidence=True`. Путь присутствовал во всех семи исходных выдачах. Точная строка прошла сверку с Git в 1 из 7 случаев до изменения и в 7 из 7 после. Состав примеров намеренно проверяет запросы с явной координатой.

Для каждого пути выбирается первая указанная положительная координата. Если выбранный фрагмент уже содержит эту строку после обрезки, дополнительный запрос к индексу пропускается. В остальных случаях используется самый узкий чанк целевой ветки, содержащий строку, и отрывок, начинающийся не более чем за четыре строки до неё. Для явных координат проверяется итоговый объём с учётом заголовков и номеров строк. Если итоговая обрезка скрывает координату, её блок продвигается вперёд, а при необходимости сокращается до одной строки. Если строка отсутствует, не помещается или вспомогательное чтение недоступно, сохраняется основной найденный фрагмент.

Отдельно проверены два сценария с 60 символами исходного текста на файл. При двух файловых слотах обрезка второго блока давала `path_unseen`. При одном слоте обрезка отрывка с запрошенной десятой строкой давала `outside_excerpt`. После учёта размера рендера обе строки получили `verified` при прежнем бюджете и том же количестве файловых слотов. Контроль с 975 символами на файл подтвердил прежний порядок блоков, когда нужная строка уже видна. Эти сценарии выполнены на локальных Git-фикстурах отдельно от семи запросов из таблицы.

Автоматические проверки используют локальные Git-фикстуры для обеих секций, отдельный ParadeDB для проверки ограничений репозитория и ветки и имитацию отказа при чтении координаты:

```bash
python -m pytest -q tests/mcp/test_context_limits_wiring.py tests/mcp/test_subqueries.py
python -m pytest -q -m integration tests/index/test_store_hybrid.py -k covering_lines
```
