## Воспроизведение

Пересчёту нужны объектная история текущего репозитория и локальный клон [pytest](https://github.com/pytest-dev/pytest) с объектами исходного SHA `c7ee55993b77315f0031b629a2fb7db17ad5cee1` и итогового SHA `acd445a3f3c2d573e9918734c99eb58954fbabb6`. Контекст внешней задачи относится к [предложению pytest #7777](https://github.com/pytest-dev/pytest/issues/7777) и [PR #11646](https://github.com/pytest-dev/pytest/pull/11646). Лицензия встроенных фрагментов взята из этого Git-снимка. [MIT](pytest-LICENSE)

```sh
python -m eval.pri326.replay score \
  --archive eval/pri326/responses.json.gz \
  --clone "pytest-dev/pytest=$pytest_clone" \
  --output "$replay_dir/metrics.json"
cmp eval/pri326/metrics.json "$replay_dir/metrics.json"
```

Команда `pack` принимает JSON-массив случаев с полями `key`, `base_sha`, `input`, `obligatory`, `read_only` и `contexts` для двух вариантов `base` и `reframe`. Для чужого репозитория указывают `repo`. При наличии `solution_sha` пересчёт сверяет первый родитель с базой. Ответы передаются как словарь вида `KEY-r1-base`. Каждый содержит идентичность запуска, хеш отправленного JSON и поля первого ответа существующего сценария PRI-278. Номера повторов задаются `--repeats`. Офлайн-пересчёт проверяет версию входа, неизменность записей, точные Git-строки и подтверждает ссылки штатным `BriefEvidence`.

Отчёт выдаёт результаты всех запланированных запусков и отдельно полные симметричные пары первых ответов. Пропущенный ответ учитывается в запланированном знаменателе. Для пустого слоя медиана равна `null`. Это позволяет считать отдельный корпус крупных задач и видеть влияние пропусков в парном сравнении.
