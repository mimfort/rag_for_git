# PRI-278. Потери контекста при подготовке брифа solve-task

Эксперимент от 21.11.2026. На 20 исторических задачах вручную размечено 195 пар «задача — файл». Из них 149 обязательных изменённых файлов и 46 неизменённых зависимостей. В базовом гибридном прогоне 101 размеченный файл дошёл до секции кода, из них 71 попал в бриф Luna. Из 124 пропусков 94 возникли до передачи контекста модели. Во всей выборке чаще всего нужного файла не было в начальных пулах поиска. На пяти крупных задачах наиболее частой отдельной причиной стал файловый лимит.

Раннее исключение тестовых чанков подняло медиану покрытия ядра в секции кода по трём крупным отложенным задачам с 45,0 до 57,9 %. Медиана покрытия в брифах этих задач осталась 40,0 %. По шести отложенным задачам медиана в брифах снизилась с 40,0 до 36,7 %. По критерию карточки изменение не рекомендовано к внедрению.

[Отдельный парный прогон](pool_size/report.md) проверяет расширение начальных пулов BM25 и ANN на том же корпусе.

[В следующем цикле](followup/report.md) проверены порядок графовых соседей и переносимая MCP-проверка ссылок.

[Новый контрольный корпус](independent/report.md) проверяет направленные графовые зависимости на десяти других задачах.

[Пересчёт PRI-293](pri293.md) проверяет ссылки по полностью видимым строкам в обоих корпусах. Числа по брифам в этом отчёте относятся к исторической версии `path-only-v1`.

## Корпус и условия

- [Карточка PRI-278](https://ru.yougile.com/team/686c049c8af8/#PRI-278) задаёт эксперимент. Предпроверка reviewer на `main` с SHA `2a8dc4972c3898bc9de5aabc6d84fbcd018fc8df` вернула карточку без пробелов. Инкрементальная синхронизация перечислила 133 карточки без ошибок.
- [Корпус и ручная разметка](corpus.json) содержат входной запрос, источник его постановки, полный SHA базы и решения, группу и назначение каждого файла. Разметку сверили с наличием пути в базовом дереве и его статусом в diff. В ядро входят файлы, необходимые для реализации и уже существовавшие до неё. В зависимости входят неизменённые файлы, полезные для понимания механизма. Созданные при исправлении файлы исключены из знаменателей. Индексируемость не была условием разметки.
- Крупной считалась задача с ядром от десяти файлов. До просмотра выдачи зафиксировали 14 задач подбора, из них две крупные, и шесть отложенных, из них три крупные. Деление стратифицировано по размеру ядра. Это разделение внутри одного репозитория, с пересечением подсистем.
- Каждый запрос представляет собой краткую формулировку проблемы и требований из раздела Task первого сохранённого брифа. Подсказки из разделов с решениями, списков изменённых файлов и итоговых патчей в запросы не добавлялись. У шести брифов первая запись в Git совпадает с коммитом исправления, поэтому неизменность формулировок с момента создания карточки для них не подтверждена.
- Код поискового прогона взят из `2ae5721df4e4deb608b8b5fcf6fe6041167c8099`. При подготовке кеша векторов использован `bfcefdf96b9ea67beea766aa75adf0acbbcbcdc2` с теми же чанкованием и эмбеддером. Из каждого базового дерева восстановлен индекс Python-чанков с правилами исключения этого дерева. Ранжирование использует pg_search 0.24.0, pgvector 0.8.2, Voyage `voyage-code-3` и `rerank-2.5`. Из 9011 уникальных текстов 7880 векторов взяты из действующего индекса по хешу содержимого. Для 1131 текста векторы вычислены заново. Индексы прогона строились во временных таблицах.
- BM25 и ANN возвращают до 30 чанков. У гибрида RRF с `k=60` оставляет до 30 кандидатов. Для кандидатов, найденных только ANN, порог косинусной дистанции равен 0,65. В варианте с реранжированием переупорядочен весь допустимый гибридный пул. Затем каждый вариант расширяет первые 15 чанков на один шаг по синтаксическому графу и форматирует максимум 20 файлов, по одному чанку на файл и с целевым пределом 975 символов исходного текста на блок.
- В опыте изолирована секция кода. На каждый исторический снимок приходится один запрос и заново построенный граф Tree-sitter. Исторические сводки, поиск похожих задач, подмешивание их diff, секция примеров тестов и дополнительные обращения модели в замер не входят. Результаты характеризуют эту воспроизводимую конфигурацию replay.
- Брифы составлены в Codex CLI 0.170.0 с явно указанной `gpt-6-luna`, уровень рассуждения `low`. В каждый запрос передавались две или четыре задачи с постановками и отрендеренными фрагментами. Инструменты, эталон и патчи модель не получала. Покрытие оценивается по путям. Путь вне переданного контекста попаданием не считается, строка проверяется отдельно.

## Сравнение поисковых вариантов

Recall@10 и nDCG@10 рассчитаны для десяти уникальных путей перед графовым расширением по объединённой разметке с бинарной релевантностью. Core-recall рассчитан по обязательным файлам, context-recall — по зависимостям для чтения. В таблице приведены медианы по задачам. Объём указан для отрендеренного текста. p95 рассчитан методом ближайшего ранга по одному измерению на задачу и вариант. Время включает запросы поиска, получение вектора при необходимости, реранжирование, расширение по готовому графу и рендер. Построение индекса и графа измерено отдельно. При N=5 p95 совпадает с максимальным значением.

| BM25 | Обычные | 15 | 33,3 % | 33,0 % | 60,0 % | 50,0 % | 17 660 | 0,011 |
| BM25 | Крупные | 5 | 26,9 % | 60,2 % | 41,7 % | 0,0 % | 18 224 | 0,013 |

| ANN | Обычные | 15 | 33,3 % | 44,4 % | 60,0 % | 75,0 % | 14 778 | 2,657 |

Реранжирование перенесло в отрендеренный контекст шесть размеченных пар и вытеснило шесть относительно гибрида. Медиана покрытия ядра крупных задач выросла с 45,0 до 50,0 %, при этом по всем задачам медиана покрытия зависимостей снизилась с 66,7 до 50,0 %. Медиана общей полноты ядра выросла, средняя попарная дельта составила −0,15 п.п. p95 гибрида с реранжированием выше на 1,443 с. Сопоставление задержек описательное, поскольку сетевой прогон не повторялся, а порядок вариантов и прогрев могли повлиять на отдельные измерения.

## Первая стадия пропуска

Классификация учитывает восстановление контекста на поздней стадии. Граф доставил до секции кода 36 размеченных пар, отсутствовавших в квалифицированном гибридном пуле. Для остальных путей [трассировка](per_file.tsv) показывает ранг в обоих источниках, прохождение RRF, попадание после графа и лимита, ранг реранкера и наличие в брифе.

| Первая причина итогового пропуска | Все | Обычные | Крупные | Ядро | Зависимости |
|---|---:|---:|---:|---:|---:|
| В снимке индекса отсутствовал чанк файла | 26 | 13 | 13 | 26 | 0 |
| Файл не попал в начальные пулы BM25 и ANN | 33 | 15 | 18 | 22 | 11 |
| Кандидат оказался за срезом RRF | 5 | 3 | 2 | 5 | 0 |
| Файловый лимит после графового расширения | 30 | 5 | 25 | 23 | 7 |
| Модель пропустила видимый файл при составлении брифа | 30 | 19 | 11 | 20 | 10 |
| Всего пропусков | 124 | 55 | 69 | 96 | 28 |

Отдельных пропусков на пороге ANN или при рендере заголовков после файлового отбора не зафиксировано. Из 26 отсутствовавших в индексе пар 24 относятся к Markdown, SQL и YAML, две — к Python-файлу, по которому чанкование не вернуло символов. Для исходного гибрида медиана полноты ядра по всем задачам снизилась с 56,9 % в секции кода до 40,0 % в брифе. По крупным задачам она снизилась с 45,0 до 40,0 %. Медиана покрытия зависимостей в брифе составила 41,7 % на всей выборке и 0 % на крупных задачах.

## Проверка раннего исключения тестовых чанков

В базовом режиме тестовые чанки участвуют в первичных пулах, затем отбрасываются при сборке секции кода. В изменённом запросе добавлен фильтр тестов до срезов BM25 и ANN. Пул по-прежнему ограничен 30 чанками, а файловый и символьный бюджеты заданы прежними настройками. На 14 задачах подбора медиана покрытия ядра в секции кода выросла с 52,8 до 58,6 %, на двух крупных — с 42,4 до 58,9 %. После этого проверен один вариант на шести отложенных задачах.

| Задача | Размер | Core-recall в секции кода | Core-recall в брифе Luna |
|---|---|---:|---:|
| PRI-215 | Крупная | 45,0 % → 45,0 % | 40,0 % → 40,0 % |
| PRI-225 | Крупная | 21,1 % → 57,9 % | 10,5 % → 10,5 % |
| PRI-241 | Обычная | 66,7 % → 66,7 % | 33,3 % → 33,3 % |
| PRI-256 | Обычная | 60,0 % → 40,0 % | 40,0 % → 20,0 % |
| PRI-257 | Крупная | 58,3 % → 58,3 % | 41,7 % → 50,0 % |
| PRI-275 | Обычная | 100,0 % → 100,0 % | 100,0 % → 100,0 % |

На отложенной выборке критерий внедрения не выполнен. Одна крупная задача улучшилась на уровне брифа, у двух других результат совпал. По обычным задачам просела PRI-256. Медиана покрытия зависимостей в секции кода упала с 62,5 до 37,5 %, а медиана в брифах осталась 25,0 %. При одинаковом лимите в 20 файлов медиана фактически переданных символов выросла с 16 427 до 18 892. Подробные парные показатели и разбивка задержек по размеру задачи сохранены в [результатах](results.json).

## Источники, расход и границы вывода

По всем 20 задачам получены результаты четырёх поисковых вариантов и парного сравнения с тестовым фильтром. Всего составлено 26 брифов. Отказов ParadeDB, векторизации, реранжирования и генерации в учтённых прогонах не зарегистрировано. Во время подготовки встречались предупреждения обновления списка моделей Codex и загрузки токенизатора, после которых прогоны завершились. Luna вернула 22 ссылки на неподтверждённый путь или строку в 20 базовых брифах, включая 13 ссылок на пути вне переданной секции. На шести брифах с ранним фильтром таких ссылок было пять, включая две на пути вне секции.

В восьми вызовах Luna учтено 306 498 входных и 6 524 выходных токена. Контрольный бриф на подборе и отложенной группе вместе занял 228 197 входных и 5 044 выходных токена. Для шести брифов с ранним фильтром расход составил 78 301 и 1 480 токенов соответственно. Эти показатели включают ввод Codex CLI. Отдельно имел место пробный короткий вызов для проверки доступности модели, который не входит в экспериментальные показатели.

Оценка покрывает файлы, а не полноту или точность сведений о них. Разметка выполнена одним разметчиком по постановкам, Git и изменениям решения. По одному запуску Luna на условие и 20 задачам одного репозитория нельзя оценить устойчивость вывода к вариативности модели или перенести результат на другие проекты. Польза для разработки и прохождение приёмки реализаций требуют проверки полного цикла.

## Воспроизведение

[Архив свидетельств](evidence.jsonl.gz) содержит пошаговые ранги и оценки кандидатов, фактически переданные фрагменты, брифы, статусы источников и замеры. Таблица по файлам и агрегаты пересчитываются из архива без сетевых вызовов.

```bash
.venv/bin/python -m eval.pri278.report --evidence eval/pri278/evidence.jsonl.gz --output /tmp/pri278-recomputed
```

Для повторного прогона запустить из корня клона с рабочей конфигурацией ParadeDB и Voyage. Исходники конвейера закрепляются через отдельную распаковку Git. Временный рабочий каталог сохраняет эмбеддинги и сырые результаты.

```bash
pri278_work=$(mktemp -d)
mkdir -p "$pri278_work/pipeline"
git archive 2ae5721df4e4deb608b8b5fcf6fe6041167c8099 | tar -x -C "$pri278_work/pipeline"
cp -R eval/pri278 "$pri278_work/pipeline/eval/"
PYTHONPATH="$pri278_work/pipeline" .venv/bin/python -P -m eval.pri278.replay --work "$pri278_work" --split tune
PYTHONPATH="$pri278_work/pipeline" .venv/bin/python -P -m eval.pri278.replay --work "$pri278_work" --split holdout
PYTHONPATH="$pri278_work/pipeline" .venv/bin/python -P -m eval.pri278.replay --work "$pri278_work" --split tune --production-only --hybrid-only
PYTHONPATH="$pri278_work/pipeline" .venv/bin/python -P -m eval.pri278.replay --work "$pri278_work" --split holdout --production-only --hybrid-only
.venv/bin/python -m eval.pri278.briefs --work "$pri278_work" --input tune-30 holdout-30 holdout-30-prod
.venv/bin/python -m eval.pri278.report --work "$pri278_work" --output "$pri278_work/recomputed"
```
